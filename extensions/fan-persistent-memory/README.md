# fan-persistent-memory

Расширение персистентной памяти для FAN (Filin Agent Next). Обеспечивает долговременное хранение информации с гибридным RAG-поиском (FTS4 + векторные эмбеддинги) для сессий ИИ-агента.

## Возможности

- **Семантическое хранение** — сохранение, поиск, обновление и удаление памятей между сессиями
- **Гибридный RAG-поиск** — комбинация FTS4 полнотекстового поиска и векторных эмбеддингов (Ollama)
- **Авто-извлечение** — эвристическое извлечение фактов из диалогов
- **Пайплайн обслуживания** — автоматический decay confidence, дедупликация, кластеризация, очистка
- **Области видимости** — памяти могут быть привязаны к проекту или быть глобальными
- **Категории и теги** — организация памятей по типу: operator, preference, project, event, instruction, decision
- **Санитизация** — автоматическая маскировка API-ключей, паролей, токенов
- **Graceful degradation** — при недоступности Ollama переключается на FTS-only режим

## Инструменты (6)

| Инструмент | Описание |
|-----------|----------|
| `memory_remember` | Сохранить новую память |
| `memory_search` | Поиск памятей по запросу (FTS + векторный) |
| `memory_update` | Обновить существующую память |
| `memory_forget` | Архивировать память (soft delete) |
| `memory_promote` | Повысить проектную память до глобальной |
| `memory_demote` | Понизить глобальную память до проектной |

## Команды

- `/memory` — Интерактивное управление памятью (статистика, список, поиск, просмотр, архивация, восстановление, ревью, категории)
- `/memory-maintain` — Ручной запуск пайплайна обслуживания

## Хранение данных

- **Глобальная БД:** `~/.fan/agent/memory/global.db` — памяти, доступные во всех проектах
- **Проектная БД:** `<project>/.fan/memory/project.db` — памяти, привязанные к проекту
- **Конфиг:** `~/.fan/agent/memory/config.json` — настройки расширения

## Конфигурация

Конфигурация находится в `~/.fan/agent/memory/config.json`. При первом запуске создаётся автоматически с дефолтными значениями.

### embeddings — Настройки эмбеддингов

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `model` | `"nomic-embed-text"` | Модель Ollama для генерации эмбеддингов |
| `ollamaBaseUrl` | `"http://localhost:11434"` | URL Ollama сервера |
| `dimension` | `768` | Размерность вектора эмбеддинга |
| `fallbackToFTSOnly` | `true` | При ошибке Ollama — fallback на FTS-only режим |

### retrieval — Настройки поиска

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `maxMemoriesPerQuery` | `5` | Максимум памятей в результате поиска |
| `maxInjectionChars` | `2000` | Максимальное кол-во символов для инжекции в контекст |
| `candidatePoolSize` | `10` | Размер пула кандидатов перед финальной выборкой |
| `ftsPoolSize` | `15` | Сколько результатов брать из FTS |
| `vectorPoolSize` | `15` | Сколько результатов брать из векторного поиска |
| `llmRerankThreshold` | `5` | Порог для LLM реранжирования |
| `minRetrievalScore` | `0.3` | Минимальный composite score для включения в результат |

#### retrieval.weights — Веса composite scoring

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `fts` | `0.30` | Вес FTS-ранжирования |
| `vector` | `0.30` | Вес векторного сходства |
| `recency` | `0.15` | Вес давности доступа (экспоненциальный decay) |
| `frequency` | `0.15` | Вес частоты использования (log-based) |
| `confidence` | `0.10` | Вес confidence памятей |

При недоступности Ollama вес `vector` пропорционально распределяется между остальными весами.

### maintenance — Настройки обслуживания

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `intervalHours` | `12` | Интервал автоматического обслуживания (часы) |
| `confidenceDecay.30d` | `0.85` | Множитель confidence для памятей старше 30 дней |
| `confidenceDecay.90d` | `0.70` | Множитель confidence для памятей старше 90 дней |
| `confidenceDecay.180d` | `0.50` | Множитель confidence для памятей старше 180 дней |
| `deduplicationThreshold` | `0.90` | Порог косинусного сходства для дедупликации |
| `clusterTagSimilarity` | `0.5` | Порог схожести тегов для кластеризации |
| `clusterVectorSimilarity` | `0.7` | Порог векторного сходства для кластеризации |
| `summarizationMinClusterSize` | `5` | Минимальный размер кластера для суммаризации |
| `hardDelete` | `false` | Удалять ли архивированные памяти навсегда |
| `hardDeleteMinAge` | `365` | Возраст (дни) для hard delete |

### intelligence — Настройки авто-извлечения

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `autoExtract` | `true` | Включить автоматическое извлечение фактов |
| `extractMinTurns` | `5` | Минимальное количество ходов перед извлечением |
| `extractMinMessages` | `3` | Минимальное количество сообщений для анализа |

## Принцип работы поиска

1. **FTS4-поиск** — полнотекстовый поиск по content, summary и tags. Токенизация с фильтрацией стоп-слов (английские + русские). Используется OR-объединение токенов для максимального recall.
2. **Векторный поиск** — генерация эмбеддинга запроса через Ollama, косинусное сходство с сохранёнными векторами. Минимальный порог: 0.3.
3. **Composite scoring** — объединение FTS-ранка, векторного скоринга, давности, частоты и confidence в единый score [0, 1].
4. **Нормализация** — FTS-ранки нормализуются независимо для каждой БД (global/project). Векторные scores нормализуются из [-1, 1] в [0, 1].

## Зависимости

- `sql.js` (WASM) — SQLite3 без нативных зависимостей
- `@sinclair/typebox` — валидация параметров инструментов
- Ollama (опционально) — для векторных эмбеддингов; при недоступности — FTS-only режим

## Устранение неполадок

### Ollama недоступен
Если статус показывает "🧠 Memory: FTS-only (Ollama down)":
1. Проверьте что Ollama запущена: `ollama list`
2. Убедитесь что модель установлена: `ollama pull nomic-embed-text`
3. Проверьте URL в конфиге: `~/.fan/agent/memory/config.json`

### Памяти не находятся
1. Проверьте что памяти не архивированы: используйте `/memory` → список
2. Проверьте scope: проектные памяти доступны только в рамках проекта
3. Попробуйте другие ключевые слова — FTS использует OR-поиск

### Ошибки в логах
Все ошибки логируются с префиксом `[persistent-memory]`. Проверьте вывод агента.
