# FAN Loop 🔄

Автономный loop-механизм для FAN: итеративное выполнение задач до выполнения критериев приёмки.

## Установка

Расширение устанавливается через FAN Store:

```bash
fan store install fan-loop
```

Или вручную скопировать в `~/.fan/agent/extensions/fan-loop/`.

## Использование

### Интерактивный режим

```
/loop
```

Запускает диалог, где нужно ввести:
1. **Описание задачи** — что нужно сделать
2. **Критерии приёмки** — как проверить что задача выполнена
3. **Максимум итераций** — лимит на случай если задача не сходится (default: 10)
4. **Модель** — опционально, какая модель будет выполнять задачу

### Режим командной строки

```
/loop "описание задачи" --criteria "критерии" --max-iterations 10 --model "model-name"
```

### Параметры

| Параметр | Алиас | Описание |
|----------|-------|----------|
| task (первый аргумент) | — | Описание задачи (обязательно) |
| `--criteria` | `-c` | Критерии приёмки (обязательно) |
| `--max-iterations` | `-m` | Максимум итераций (default: 10, max: 50) |
| `--model` | — | Модель для выполнения задачи |
| `--interactive` | `-i` | Запустить интерактивный опрос |
| `--help` | `-h` | Показать справку |

### Примеры

```bash
# Рефакторинг с проверкой тестов
/loop "Рефакторинг модуля auth" -c "Все тесты проходят, билд успешен"

# Исправление бага с ограничением по итерациям
/loop "Исправить баг #123" -c "Баг не воспроизводится" -m 5

# С указанием модели
/loop "Добавить JSDoc во все функции" -c "Все экспортируемые функции документированы" --model "zai/glm-4.5-air"
```

## Как это работает

```
Пользователь → /loop "задача" --criteria "..." --max-iterations 10
    │
    ▼
LoopController запускает цикл:
    │
    ├── Итерация 1: запустить агента → собрать результат → проверить критерии
    │   ├── PASS  → ✅ Цикл завершён
    │   ├── FAIL  → Итерация 2 с контекстом предыдущей попытки
    │   └── FAIL  → ... (до max-iterations)
    │
    └── Stalemate detection: 3 одинаковые итерации → ⛔ Цикл прерван
```

**Ключевые механики:**
- **Внешний контроль** — расширение управляет циклом, а не агент сам себя перезапускает
- **Файловая память** — каждая итерация использует свежий контекст, не накапливая историю в context window
- **Двойная проверка** — сначала выполнение задачи, затем верификация критериев отдельным LLM-вызовом
- **Stalemate detection** — если 3 последние итерации дали одинаковый результат, цикл прерывается
- **Safety net** — лимит итераций (max 50), stall-таймер (5 мин на итерацию)

## Архитектура

```
fan-loop/
├── package.json        # Метаданные расширения
├── config.json         # Конфигурация по умолчанию (defaultMaxIterations, defaultModel)
├── index.ts            # Entry point: /loop команда, парсинг аргументов, интерактивный опрос
├── loop-controller.ts  # LoopController: RPC-воркеры, цикл итераций, верификация критериев
└── types.ts            # TypeScript типы: LoopConfig, LoopState, LoopIteration, ParsedLoopArgs
```

### Ключевые типы

- **`LoopConfig`** — конфигурация цикла (`maxIterations`, `model`)
- **`LoopState`** — состояние цикла (`status`, `iterations[]`, `finalVerdict`)
- **`LoopIteration`** — одна итерация (`number`, `result`, `verdict`, `error`)
- **`ParsedLoopArgs`** — результат парсинга аргументов `/loop`

### Механизм RPC-воркеров

Каждая итерация запускает `fan --mode rpc` как дочерний процесс. Коммуникация через JSONL по stdin/stdout:

1. **Выполнение задачи** — отправляется промпт с задачей + контекст предыдущих итераций
2. **Верификация критериев** — отдельный вызов с результатом итерации, возвращает `PASS`/`FAIL`/`PARTIAL`

## Зависимости

- **FAN Core** — расширение использует `ExtensionAPI` из `@itone/fan-coding-agent`
- **fan binary** — для запуска RPC-воркеров (`fan --mode rpc`)
- **Node.js** — `child_process.spawn`, `fs`, `crypto`

## Конфигурация

Файл `config.json` содержит значения по умолчанию:

```json
{
  "defaultMaxIterations": 10,
  "defaultModel": ""
}
```

## Разработка

```bash
# Установить расширение локально
cp -r fan-loop ~/.fan/agent/extensions/

# Перезапустить fan
fan
```
