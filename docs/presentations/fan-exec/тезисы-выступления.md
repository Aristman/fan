# FAN — тезисы выступления для руководства

**Формат:** 10–12 минут доклад + 5 минут Q&A · 11 слайдов (`slides.html`)
**Аудитория:** руководство и менеджеры (нетехническая)
**Цель:** показать продукт, его преимущества и планы развития; получить обратную связь по roadmap

---

## Элеватор-питч (30 секунд, если спросят в лифте)

> FAN — это ИИ-ассистент для разработчиков, который работает полностью локально на их машинах. Код и данные никуда не уходят. Он умеет не просто отвечать в чате, а самостоятельно решать задачи: распределяет работу между командой ИИ-агентов, проверяет результат и контролирует расходы на ИИ.

---

## Тезисы по слайдам

### Слайд 1 — Титул (~30 сек)
- Представиться: проект FAN — Fast Agents Network.
- Одна фраза о сути: «многоагентный ИИ-ассистент, который живёт на машине разработчика, а не в чужом облаке».
- Перечислить функционал с подводки: читает и пишет код, запускает тесты, чинит баги, пишет документацию — автономно.

### Слайд 2 — Контекст и решение (~1.5 мин)
- Три боли бизнеса: приватность кода, фрагментация инструментов, неконтролируемые расходы на токены.
- **Переход к решению:** FAN закрывает все три боли — один локальный рантайм для терминала, браузера и IDE.
- Проговорить бейджи внизу: локальные данные, оркестратор, 20+ провайдеров, все ОС.

### Слайд 3 — Архитектура (~1.5 мин)
- Не углубляться в детали: «клиенты → шлюз → рантайм → модели».
- Подчеркнуть: единый API = любой клиент подключается без переделки ядра.
- Ключевая фраза внизу слайда: **«данные — на диске пользователя, наружу уходят только промпты»**.

### Слайд 4 — Оркестратор (~1.5 мин) ⭐ главный слайд
- Аналогия: **«не один чат-бот, а мини-команда разработки»**.
- Координатор разбивает задачу, воркеры исполняют, верификатор проверяет.
- 8 типов воркеров: от разведки кода до написания документации.
- Автономность: пользователь ставит цель — система сама доводит до результата.

### Слайд 5 — Экономика (~1 мин)
- Роутинг: простые задачи → дешёвая модель, сложные → мощная. Экономия «из коробки».
- Budget Tracker: лимиты по деньгам и токенам, визуализация в Dashboard.
- Fallback: сбой провайдера ≠ остановка работы.
- **Месседж для CFO:** «счёт за ИИ становится предсказуемым».

### Слайд 6 — Сценарии использования (~1 мин)
- Разработчик — терминал (`fan`). Менеджер/аналитик — веб-Dashboard (`fan --web`).
- IDE-плагин подключается к фоновому серверу. Скрипты/CI — через `fan -p`.

### Слайд 7 — Экосистема (~1 мин)
- FAN Store: 10 расширений, 12 скиллов, установка одной командой.
- **Бандлы и переносимость:** кастомизация через бандлы, унифицированные пакеты передаются между экземплярами FAN — настройка целой команды в один клик.
- Платформа растёт без изменения ядра — как маркетплейс.

### Слайд 8 — Качество (~45 сек)
- 717+ unit-тестов, все зелёные. Ручное тестирование: 18/18 оркестратор, 26/30 Dashboard.
- 18 багов найдено и исправлено **до** пользователя.

### Слайд 9 — Дифференциация (~1 мин)
- Выбрать 3 из 6 под аудиторию. Для security-minded: приватность. Для CFO: бюджет. Для CTO: оркестратор + расширяемость.

### Слайд 10 — Дорожная карта (~1 мин)
- Super-Orchestrator v3 — многоуровневая иерархия агентов (спецификация готова).
- Плагин IntelliJ IDEA — выход в основную IDE (спецификация готова).
- Session Analytics — самоанализ качества работы агента.
- **Облачный агент** — работа с репозиториями и удалённое управление.
- Здесь остановиться и собрать обратную связь по приоритетам.

### Слайд 11 — Итог (~30 сек)
- Повторить три слова: **приватный, многоагентный, расширяемый**.
- Быстро пройтись по 6 карточкам преимуществ.
- Финал: «Сегодня — инструмент разработчиков. Завтра — платформа корпоративной AI-разработки».

## Подготовка к Q&A

| Вероятный вопрос | Короткий ответ |
|---|---|
| «Сколько стоит эксплуатация?» | Сам FAN бесплатен (локальный). Расходы — только API-ключи ИИ-провайдеров, и они под контролем Budget Tracker. Можно вообще на локальных моделях (Ollama) — тогда ноль. |
| «Что с безопасностью?» | Нет облачного сервера FAN. Наружу уходят только промпты к выбранному провайдеру. Опция — полностью локальные модели, тогда ничего не уходит. |
| «Чем отличается от Copilot / Cursor?» | Они — облачные и привязаны к одному клиенту. FAN — локальный рантайм с мультиклиентностью, многоагентным оркестратором и контролем бюджета. |
| «Как начать пользоваться?» | Одна команда установки (one-liner или бинарник), `fan init` — мастер настройки за 2 минуты, `fan doctor` — диагностика. |
| «Что если провайдер ИИ упадёт?» | Fallback-цепочки: автопереключение на резервную модель без потери работы. |
| «Можно ли расширять под наши процессы?» | Да: FAN Store (расширения, скиллы, бандлы), MCP-интеграции, собственные скиллы в формате SKILL.md. Пакеты переносимы между экземплярами FAN. |
| «Как развернуть на команду?» | Настроить один экземпляр, собрать бандл и передать команде — унифицированные пакеты ставятся одной командой. |
