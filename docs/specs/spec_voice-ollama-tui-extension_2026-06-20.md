# Спецификация: Расширение голосового ввода через Ollama для TUI FAN

- **Тип**: Новая фича (FAN Extension)

## 1. Обзор

### 1.1 Цель

Создать FAN-расширение `voice-ollama-tui`, которое позволяет пользователю в терминальном интерфейсе FAN (TUI) диктовать текст: записывать аудио с микрофона, распознавать речь через локальный `whisper.cpp` и опционально постобрабатывать результат через Ollama-модель. Итоговый текст вставляется в строку ввода TUI.

### 1.2 Контекст

Ввод длинных промптов и сообщений вручную в TUI FAN занимает время и неудобен без полноценной клавиатуры. Существующее исследование (`docs/research/idea-lab/voice-input/Расширение голосового ввода через Ollama для TUI — анализ.md`) показало, что оптимальное решение — standalone-расширение с двухэтапным pipeline: аудио → whisper.cpp → опциональная Ollama-постобработка → TUI. Прямая передача аудио в Ollama отклонена из-за нестабильности API.

### 1.3 Описание решения

Расширение регистрирует команду `/voice` и настраиваемый шорткат. При активации:

1. Показывается overlay с индикатором записи.
2. Запускается запись аудио через `ffmpeg` (приоритетная утилита) во временный файл.
3. Пользователь завершает запись вручную по клавише (`Enter` / `Escape`) или по таймауту.
4. Аудио конвертируется в WAV 16 кГц моно.
5. `whisper.cpp` CLI распознаёт текст.
6. Если включена Ollama-постобработка, распознанный текст отправляется в Ollama `/api/chat`.
7. Результат вставляется в редактор TUI через `ctx.ui.setEditorText()`.

Модель `whisper.cpp` скачивается автоматически при первом запуске в `~/.fan/models/speech/`. Модель Ollama выбирается через автообнаружение доступных моделей.

## 2. Функциональные требования

### 2.1 Основные функции

- **F-1 Регистрация команды и шортката**: Расширение регистрирует `/voice` и настраиваемый шорткат (по умолчанию `Ctrl+Shift+V`).
- **F-2 Запись аудио**: Запись с микрофона через `ffmpeg` (с fallback на `sox`/`arecord` при необходимости) во временный файл.
- **F-3 Ручная остановка записи**: Пользователь завершает запись нажатием `Enter` (принять) или `Escape` (отменить).
- **F-4 Распознавание речи**: Вызов `whisper.cpp` CLI для транскрибации аудио в текст.
- **F-5 Автозагрузка whisper-модели**: При отсутствии модели расширение скачивает `ggml-base.bin` в `~/.fan/models/speech/`.
- **F-6 Опциональная Ollama-постобработка**: Распознанный текст отправляется в Ollama `/api/chat` для улучшения пунктуации, исправления ошибок, структурирования.
- **F-7 Автообнаружение моделей Ollama**: Расширение получает список доступных моделей через `GET /api/tags` и предлагает выбрать.
- **F-8 Вставка результата**: Итоговый текст вставляется в строку ввода TUI через `ctx.ui.setEditorText()`.
- **F-9 Индикаторы состояния**: Overlay показывает статус: «Запись...», «Распознавание...», «Обработка...», «Готово».
- **F-10 Обработка ошибок**: При сбое на любом этапе показывается понятное уведомление, TUI не портится.

### 2.2 Пользовательские сценарии

#### Сценарий 1: Быстрая диктовка без Ollama

**Предусловия:** Расширение установлено; whisper.cpp и модель доступны.

**Шаги:**
1. Пользователь нажимает `Ctrl+Shift+V`.
2. Появляется overlay «Запись... Говорите».
3. Пользователь произносит текст.
4. Пользователь нажимает `Enter`.
5. Overlay меняется на «Распознавание...».
6. Распознанный текст появляется в строке ввода TUI.

**Ожидаемый результат:** Текст вставлен в редактор, можно редактировать и отправить.

#### Сценарий 2: Диктовка с Ollama-постобработкой

**Предусловия:** Ollama запущена, в конфиге `ollamaEnabled: true`, выбрана модель.

**Шаги:**
1–4. Как в сценарии 1.
5. Overlay меняется на «Распознавание...».
6. Overlay меняется на «Обработка через Ollama...».
7. Улучшенный текст появляется в строке ввода TUI.

**Ожидаемый результат:** Текст отформатирован и исправлен, вставлен в редактор.

#### Сценарий 3: Первый запуск без whisper-модели

**Предусловия:** Расширение установлено, модель `ggml-base.bin` отсутствует.

**Шаги:**
1. Пользователь нажимает `Ctrl+Shift+V`.
2. Расширение обнаруживает отсутствие модели.
3. Показывается уведомление «Модель не найдена. Скачать?».
4. Пользователь подтверждает.
5. Показывается прогресс загрузки.
6. После загрузки запускается запись.

**Ожидаемый результат:** Модель загружена, запись работает.

#### Сценарий 4: Ollama недоступна

**Предусловия:** `ollamaEnabled: true`, но сервер Ollama не отвечает.

**Шаги:**
1. Пользователь активирует голосовой ввод.
2. Распознавание завершается успешно.
3. Попытка вызова Ollama возвращает ошибку соединения.
4. Расширение вставляет сырой распознанный текст.
5. Показывается уведомление «Ollama недоступна, вставлен сырой текст».

**Ожидаемый результат:** Пользователь получает текст без постобработки.

### 2.3 Бизнес-правила

- **BR-1** Расширение не должно блокировать работу TUI при ошибках.
- **BR-2** Аудио и распознанный текст не должны покидать локальную машину, если не используется внешний URL Ollama.
- **BR-3** Постобработка Ollama должна сохранять исходный смысл текста; агрессивное переформулирование запрещено.
- **BR-4** Пользователь должен иметь возможность отменить запись на любом этапе.
- **BR-5** Расширение должно работать без Ollama, если она не настроена.

## 3. UI/UX требования

### 3.1 Экраны и компоненты

- **Overlay записи**: Центрированный блок в TUI с текстом «🎙 Запись... Нажмите Enter для завершения, Esc для отмены».
- **Overlay обработки**: Текст «Распознавание...» или «Обработка через Ollama...» с анимацией.
- **Уведомления**: `ctx.ui.notify()` для ошибок и информации (модель скачана, Ollama недоступна и т.п.).

### 3.2 Взаимодействие

- Горячая клавиша по умолчанию: `Ctrl+Shift+V`.
- Команда: `/voice`.
- `Enter` — завершить запись и начать обработку.
- `Escape` — отменить запись и закрыть overlay.
- После обработки фокус возвращается в строку ввода TUI.

### 3.3 Обработка ошибок

- Нет микрофона/утилиты записи — уведомление с инструкцией по установке `ffmpeg`.
- whisper.cpp не найден — уведомление с инструкцией по установке.
- Модель не найдена — предложение скачать.
- Ollama недоступна — fallback на сырой текст + уведомление.
- Распознавание вернуло пустой текст — уведомление «Ничего не распознано».

## 4. Нефункциональные требования

### 4.1 Производительность

- Время от нажатия клавиши до начала записи: < 300 мс.
- Время распознавания фразы длиной 10 секунд на CPU с моделью `base`: < 5 секунд.
- Время постобработки Ollama: зависит от модели, цель — < 3 секунд для короткого текста.
- Максимальная длительность записи по умолчанию: 60 секунд.

### 4.2 Безопасность

- Аудиофайлы хранятся во временной директории ОС и удаляются после обработки.
- Путь к whisper-модели и Ollama-URL настраиваются пользователем.
- Расширение не отправляет данные в сторонние сервисы, кроме настроенного Ollama-сервера.

### 4.3 Надёжность

- При ошибке на любом этапе overlay закрывается, TUI остаётся в рабочем состоянии.
- Fallback на сырой текст при недоступности Ollama.
- Возможность отключить Ollama-постобработку в конфиге.

### 4.4 Масштабируемость

- Расширение рассчитано на однопользовательский локальный запуск FAN.
- Нагрузка определяется производительностью whisper.cpp и Ollama на машине пользователя.

## 5. Технические требования

### 5.1 Стек технологий

- **Язык**: TypeScript
- **Runtime**: Bun / Node.js (через jiti в FAN)
- **FAN Extension API**: `@itone/fan-coding-agent`
- **Запись аудио**: `ffmpeg` (приоритет), fallback `sox`/`arecord`
- **Распознавание речи**: `whisper.cpp` CLI
- **Постобработка**: Ollama HTTP API (`/api/chat`, `/api/tags`)
- **Конфигурация**: `.env` или JSON-файл в директории расширения

### 5.2 Архитектура

```
┌─────────────────────────────┐
│  Пользователь в TUI FAN     │
│  /voice или Ctrl+Shift+V    │
└─────────────┬───────────────┘
              ▼
┌─────────────────────────────┐
│  voice-ollama-tui           │
│  (FAN Extension)            │
│  - config                   │
│  - audio recorder           │
│  - whisper service          │
│  - ollama service           │
│  - ui overlay               │
└─────────────┬───────────────┘
              ▼
┌─────────────────────────────┐
│  ffmpeg → temp audio file   │
└─────────────┬───────────────┘
              ▼
┌─────────────────────────────┐
│  whisper.cpp CLI            │
│  → raw transcript           │
└─────────────┬───────────────┘
              ▼
    ┌─────────────────────┐

│  ctx.ui.setEditorText()     │
└─────────────────────────────┘
```

### 5.3 Интеграции

- **FAN Extension API**: `pi.registerCommand()`, `pi.registerShortcut()`, `ctx.ui.custom()`, `ctx.ui.setEditorText()`, `pi.exec()`.
- **whisper.cpp CLI**: Вызов `whisper-cli -m <model> -l <lang> -f <audio> -nt`.
- **Ollama API**:
  - `GET /api/tags` — список моделей.
  - `POST /api/chat` — постобработка текста.

- `whisperLanguage` должен соответствовать поддерживаемым языкам whisper.cpp или быть `"auto"`.

## 8. Компромиссы (Tradeoffs)

### 8.1 Расширение вместо встроенной фичи

- **Решение**: Реализовать как standalone-расширение FAN.
- **Альтернатива**: Встроить в `packages/coding-agent` или `packages/tui`.
- **Обоснование**: Изоляция от ядра, быстрая итерация, возможность публикации в FAN Store.

### 8.2 whisper.cpp вместо прямой передачи аудио в Ollama

- **Решение**: Использовать whisper.cpp для распознавания, Ollama только для текста.
- **Альтернатива**: Передавать аудио напрямую в Ollama (gemma4, nemotron3).
- **Обоснование**: API Ollama для аудио-входа не задокументирован, модели тяжёлые, риск поломок при обновлениях.

### 8.3 ffmpeg вместо sox как основной рекордер

- **Решение**: Приоритет `ffmpeg`, fallback на `sox`/`arecord`.
- **Альтернатива**: Использовать `sox` как основной рекордер.
- **Обоснование**: `ffmpeg` чаще уже установлен у разработчиков; для записи с микрофона подходит на всех платформах.

### 8.4 Автозагрузка модели

- **Решение**: Автоматически скачивать `ggml-base.bin` при первом запуске.
- **Альтернатива**: Требовать ручную установку.
- **Обоснование**: Упрощает onboarding, модель небольшая (~142 МБ).

### 8.5 Автообнаружение моделей Ollama

- **Решение**: Получать список моделей через `/api/tags` и предлагать выбрать.
- **Альтернатива**: Жёстко зашитая модель по умолчанию.
- **Обоснование**: Пользователи могут иметь разные модели; автообнаружение удобнее и не требует жёстких предположений.
