# Spec: feature-roadmap

## Метаданные
- **Дата**: 2026-05-28
- **Автор**: fan-forge
- **Статус**: Утверждена
- **Тип**: Skill (SKILL.md)

## 1. Обзор

### 1.1 Цель
Создать skill, который на основе спецификации фичи (или её описания) генерирует полный roadmap развития в парадигме TDD. Roadmap оформляется как чеклист: каждая функция — это пункт с чекбоксом, разбитый по этапам и приоритетам. Для каждой функции перечисляются TDD-тесты, которые нужно пройти для её реализации.

### 1.2 Описание решения
Skill `feature-roadmap` принимает на вход спецификацию фичи (файл или текст), парсит её, выделяет все описываемые функции/возможности, оценивает их приоритет и зависимости, группирует по этапам (фазам разработки) и генерирует:
- `docs/features/<slug>/roadmap.md` — Markdown-файл с полным roadmap в стиле чеклиста
- Mermaid-диаграмма может быть добавлена опционально (Phase 2)

## 2. Входные данные

### 2.1 Формат входа
Skill принимает аргументы при вызове:
- `/skill:feature-roadmap <path>` — путь к файлу спецификации
- `/skill:feature-roadmap <name>` — имя фичи (ищет в `docs/specs/` и `docs/features/`)
- `/skill:feature-roadmap` без аргумента — запускает интерактивный ввод

### 2.2 Формат спецификации
Ожидаемый формат — любой читаемый Markdown-файл спецификации. Skill парсит:
- Заголовки и подзаголовки (определяют структуру функций)
- Списки требований/функций
- Описания API endpoints, компонентов, моделей данных

## 3. Выходные данные

### 3.1 Структура директории
```
docs/features/<slug>/
├── roadmap.md              # Полный roadmap с чеклистом
└── README.md               # Краткое описание пакета (если нужно)
```

### 3.2 Формат roadmap.md

```markdown

> **Дата генерации:** YYYY-MM-DD
> **Источник:** <путь к спеке или описание>
```

## 4. Процесс работы скилла

### Шаг 1: Получение и парсинг входных данных
- Если передан путь к файлу — прочитать его
- Если передано имя — найти в `docs/specs/` и `docs/features/`
- Если ничего не передано — запросить у пользователя через `question`/`questionnaire`

### Шаг 2: Извлечение функций из спецификации
- Парсить заголовки, списки, секции
- Для каждой функции выделить: имя, описание, приоритет (по контексту), зависимости (по упоминаниям)
- Сгруппировать по этапам (если в спеке есть этапы) или предложить группировку

### Шаг 3: Интервью для уточнения (если нужно)
Если спецификация неполная или есть неясности — задать уточняющие вопросы через `question`/`questionnaire`

### Шаг 4: Генерация roadmap
- Создать директорию `docs/features/<slug>/`
- Сгенерировать `roadmap.md` в указанном формате
- Добавить сводную таблицу и полный чеклист по приоритетам

### Шаг 5: Представление пользователю
- Показать результат
- Спросить, нужно ли что-то изменить

## 6. Критерии тестирования

- [ ] Skill загружается через `fan` без ошибок
- [ ] `/skill:feature-roadmap <path>` корректно парсит существующую спеку
- [ ] `/skill:feature-roadmap` без аргументов запускает интерактивный ввод
- [ ] P0 функции правильно определяются и помечаются
- [ ] Зависимости между функциями корректно отражаются
- [ ] TDD-тесты генерируются для каждой функции
- [ ] Формат вывода соответствует спецификации

## 7. Риски

- Разные форматы спецификаций — нужен гибкий парсинг
- Некорректное определение приоритетов — добавить step для ручной корректировки
- Слишком длинный roadmap — группировать по этапам
