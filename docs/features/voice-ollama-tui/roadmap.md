## Этап 1: Каркас и конфигурация расширения

**Цель:** Создать структуру FAN-расширения `voice-ollama-tui`, зарегистрировать команду `/voice` и шорткат `Ctrl+Shift+V`, реализовать загрузку конфигурации из `.env`/JSON.
**Приоритет функций:** P0–P1

#### ☐ F-1.1 [CLI]: Регистрация команды `/voice` и шортката `Ctrl+Shift+V`

- **Приоритет:** P0
- **Слой:** [CLI]
- **Описание:** Расширение при загрузке регистрирует команду `/voice` и настраиваемый шорткат, который пользователь может использовать для активации голосового ввода.
- **Пользовательская история:** «Как пользователь TUI FAN, я хочу активировать голосовой ввод по команде или горячей клавише, чтобы не набирать текст вручную.»
- **Зависимости:** (none)
- **TDD-тесты:**
  - [ ] **TC-F-1.1-1:** Команда `/voice` доступна в списке команд FAN после загрузки расширения.
    - *Условие:* Расширение установлено и загружено.
    - *Шаги:* Вызвать `pi.getCommands()` и найти команду с именем `voice`.
    - *Ожидаемый результат:* Команда `voice` присутствует в списке, `source === "extension"`.
  - [ ] **TC-F-1.1-2:** Шорткат `Ctrl+Shift+V` зарегистрирован и вызывает обработчик.
    - *Условие:* Расширение загружено в интерактивном режиме.
    - *Шаги:* Отправить входную последовательность `ctrl+shift+v` и проверить, что запускается логика записи (или mock-обработчик).
    - *Ожидаемый результат:* Обработчик шортката вызван ровно один раз.
- **Критерии приёмки:**
  1. Команда `/voice` отображается в списке slash-команд FAN.
  2. Шорткат по умолчанию `Ctrl+Shift+V` активирует голосовой ввод.
  3. Имя команды и шорткат не конфликтуют со встроенными командами FAN.
- **Ожидаемый результат:** Файл `index.ts` расширения содержит вызовы `pi.registerCommand("voice", ...)` и `pi.registerShortcut("ctrl+shift+v", ...)`.
- **Оценка объёма:** S (≤ 4 ч)

## Этап 2: Аудиозапись в TUI

**Цель:** Реализовать запись аудио с микрофона через `ffmpeg` с ручной остановкой, fallback на `sox`/`arecord`, и отображение overlay с индикатором записи.
**Приоритет функций:** P0–P1

#### ☐ F-2.1 [INTEG]: Запись аудио через ffmpeg во временный файл

- **Приоритет:** P0
- **Слой:** [INTEG]
- **Описание:** Расширение запускает `ffmpeg` для записи аудио с микрофона в WAV-файл во временной директории. Поддерживается указание устройства и максимальной длительности.
- **Пользовательская история:** «Как пользователь, я хочу, чтобы расширение записывало мою речь в файл, чтобы потом распознать её.»
- **Зависимости:** F-1.1, F-1.2
- **TDD-тесты:**
  - [ ] **TC-F-2.1-1:** При вызове `recordAudio()` создаётся WAV-файл длительностью не менее 1 секунды.
    - *Условие:* `ffmpeg` доступен, микрофон подключён.
    - *Шаги:* Вызвать `recordAudio({ duration: 1 })`, дождаться завершения.
    - *Ожидаемый результат:* Файл существует, размер > 0, формат WAV (проверка через `ffprobe` или сигнатуру RIFF).
  - [ ] **TC-F-2.1-2:** При отсутствии `ffmpeg` выбрасывается ошибка `AudioRecorderError` с кодом `RECORDER_NOT_FOUND`.
    - *Условие:* `ffmpeg` отсутствует в PATH.
    - *Шаги:* Вызвать `recordAudio()`.
    - *Ожидаемый результат:* Брошена ошибка с понятным сообщением.
  - [ ] **TC-F-2.1-3:** Запись корректно прерывается по сигналу abort.
    - *Условие:* Запись запущена на 10 секунд.
    - *Шаги:* Через 500 мс вызвать `controller.abort()`.
    - *Ожидаемый результат:* Процесс ffmpeg завершён, временный файл удалён или не создан.
- **Критерии приёмки:**
  1. `ffmpeg` записывает моно-WAV 16 кГц 16 бит.
  2. Поддерживается параметр `audioDevice` из конфигурации.
  3. При ошибке записи возвращается структурированная ошибка с кодом.
- **Ожидаемый результат:** Модуль `audio-recorder.ts` с функцией `recordAudio(options)`.
- **Оценка объёма:** M (≤ 1 день)

    - *Ожидаемый результат:* `ctx.ui.notify("Ничего не распознано", "warning")` вызвано, `setEditorText` не вызван.
- **Критерии приёмки:**
  1. Распознанный текст появляется в строке ввода.

- **Ожидаемый результат:** Модуль `editor-utils.ts` с функцией `insertTranscript(ctx, text)`.
- **Оценка объёма:** S (≤ 4 ч)

## Этап 4: Ollama-постобработка и полировка

**Цель:** Реализовать опциональную постобработку распознанного текста через Ollama, автообнаружение моделей, fallback на сырой текст и финальную обработку ошибок.
**Приоритет функций:** P1–P2

#### ☐ F-4.1 [INTEG]: Автообнаружение моделей Ollama через `/api/tags`

- **Приоритет:** P1
- **Слой:** [INTEG]
- **Описание:** Расширение запрашивает список моделей у Ollama и позволяет пользователю выбрать модель для постобработки.
- **Пользовательская история:** «Как пользователь, я хочу выбирать модель Ollama из списка доступных, а не вводить имя вручную.»
- **Зависимости:** F-1.2
- **TDD-тесты:**
  - [ ] **TC-F-4.1-1:** При запущенной Ollama возвращается список моделей с именами.
    - *Условие:* Ollama доступна по `http://localhost:11434`, есть модели.
    - *Шаги:* Вызвать `listOllamaModels()`.
    - *Ожидаемый результат:* Массив строк длиной > 0, например `["llama3.2", "qwen2.5"]`.
  - [ ] **TC-F-4.1-2:** При недоступной Ollama возвращается пустой массив и ошибка соединения.
    - *Условие:* Ollama не запущена.
    - *Шаги:* Вызвать `listOllamaModels()`.
    - *Ожидаемый результат:* Пустой массив, ошибка `OLLAMA_UNREACHABLE`.
- **Критерии приёмки:**
  1. Запрос выполняется к `${ollamaBaseUrl}/api/tags`.
  2. Возвращаются только имена моделей (`name` из ответа Ollama).
  3. При ошибке соединения пользователь получает уведомление.
- **Ожидаемый результат:** Модуль `ollama-service.ts` с функцией `listOllamaModels(config)`.
- **Оценка объёма:** S (≤ 4 ч)

#### ☐ F-4.2 [INTEG]: Постобработка текста через Ollama `/api/chat`

- **Приоритет:** P1
- **Слой:** [INTEG]
- **Описание:** Распознанный текст отправляется в Ollama с системным промптом для исправления пунктуации и опечаток. Если Ollama недоступна — используется сырой текст.
- **Пользовательская история:** «Как пользователь, я хочу, чтобы текст после распознавания был с пунктуацией и без явных опечаток.»
- **Зависимости:** F-3.1, F-4.1
- **TDD-тесты:**
  - [ ] **TC-F-4.2-1:** Для входного текста "привет мир как дела" Ollama возвращает улучшенный текст с пунктуацией.
    - *Условие:* Ollama доступна, модель выбрана.
    - *Шаги:* Вызвать `improveText("привет мир как дела")`.
    - *Ожидаемый результат:* Возвращена строка, содержащая "?" или "," или "." (или исходный текст, если модель не изменила).
  - [ ] **TC-F-4.2-2:** При недоступной Ollama возвращается исходный текст и зарегистрирована ошибка.
    - *Условие:* Ollama не отвечает.
    - *Шаги:* Вызвать `improveText("привет")`.
    - *Ожидаемый результат:* Возвращена строка "привет", `ctx.ui.notify` вызвано с предупреждением.
  - [ ] **TC-F-4.2-3:** Если `ollamaEnabled === false`, функция возвращает исходный текст без вызова Ollama.
    - *Условие:* В конфиге `ollamaEnabled: false`.
    - *Шаги:* Вызвать `improveText("привет")`.
    - *Ожидаемый результат:* Возвращена строка "привет", сетевой запрос не выполняется.
- **Критерии приёмки:**
  1. Запрос выполняется к `/api/chat` с `stream: false`.
  2. Системный промпт конфигурируется пользователем.
  3. При любой ошибке Ollama используется fallback на сырой текст.
- **Ожидаемый результат:** Модуль `ollama-service.ts` с функцией `improveText(config, text)`.
- **Оценка объёма:** M (≤ 1 день)

#### ☐ F-4.3 [BIZ]: Глобальная обработка ошибок и уведомления

- **Приоритет:** P1
- **Слой:** [BIZ]
- **Описание:** Все ошибки в pipeline (запись, распознавание, Ollama) обрабатываются централизованно: overlay закрывается, TUI остаётся рабочим, пользователь получает понятное уведомление.
- **Пользовательская история:** «Как пользователь, я хочу, чтобы при сбое расширение не ломало TUI и объясняло, что произошло.»
- **Зависимости:** F-1.1, F-2.2, F-3.1, F-4.2
- **TDD-тесты:**
  - [ ] **TC-F-4.3-1:** При ошибке записи overlay закрывается и показывается `notify` с типом `error`.
    - *Условие:* `ffmpeg` недоступен.
    - *Шаги:* Вызвать `/voice`.
    - *Ожидаемый результат:* `ctx.ui.custom` завершён, `ctx.ui.notify` вызван с `type: "error"`.
  - [ ] **TC-F-4.3-2:** При ошибке распознавания TUI не блокируется и показывается уведомление.
    - *Условие:* Модель повреждена или whisper-cli падает.
    - *Шаги:* Вызвать pipeline после записи.
    - *Ожидаемый результат:* Редактор остаётся редактируемым, overlay закрыт, уведомление содержит код ошибки.
- **Критерии приёмки:**
  1. Ни одна ошибка в pipeline не приводит к зависанию TUI.
  2. Все ошибки показываются через `ctx.ui.notify()`.
  3. Временные файлы удаляются даже при ошибке.
- **Ожидаемый результат:** Модуль `pipeline.ts` с функцией `runVoicePipeline(ctx)` и централизованным `try/catch`.
- **Оценка объёма:** S (≤ 4 ч)

- **Приоритет:** P2

- **Пользовательская история:** «Как пользователь, я хочу, чтобы запись сама останавливалась, когда я перестаю говорить.»
- **Зависимости:** F-2.1
