## Обзор фичи

Расширение для fan, обеспечивающее двустороннюю работу с Atlassian Confluence Data Center. LLM-агент получает возможность читать страницы из доступных пространств с автоматической конвертацией Storage Format в Markdown, выполнять поиск по CQL, а также создавать и обновлять страницы, передавая Markdown-контент, который расширение конвертирует в Confluence Storage Format.

Расширение состоит из 6 инструментов, зарегистрированных через `fan.registerTool()`. Архитектура строится на TypeScript-клиенте `confluence.js` для общения с REST API Confluence и библиотеках `turndown` / `marked` для двусторонней конвертации форматов. Конфигурация (baseUrl, PAT, spaceKey) загружается из env-файла рядом с расширением.

## Начало работы

Перед началом разработки создать основную фичевую ветку:
```bash
git checkout develop
git checkout -b feature/fan-confluence
```
Документация пакета записывается в эту ветку. Каждый этап реализуется в отдельном worktree в `.wt/fan-confluence/`.

## Детали этапов

### Этап 1: Foundation

Создание каркаса расширения: структура директорий, `package.json` с зависимостями (`confluence.js`, `turndown`, `marked`), модуль конфигурации (загрузка из `.env`, валидация), инициализация API-клиента с PAT-аутентификацией, проверка подключения к Confluence Data Center.

**Ключевые результаты:**
- Структура расширения с `package.json` и `index.ts`
- Модуль `config.ts` — загрузка и валидация `CONFLUENCE_BASE_URL`, `CONFLUENCE_PAT`, `CONFLUENCE_SPACE_KEY`
- Модуль `client.ts` — создание экземпляра `Confluence` с PAT-аутентификацией
- Функция health check — проверка доступности API через запрос к `/rest/api/space`
- Расширение загружается в fan без ошибок (`/reload`)

**Smoke-тест:** Запустить fan с расширением, выполнить `/confluence` — получить статус подключения (OK или ошибку конфигурации).

### Этап 2: Read

Реализация инструментов для чтения данных из Confluence. Конвертация Confluence Storage Format (XHTML) в Markdown через библиотеку `turndown` с плагином GFM. Четыре инструмента: список пространств, список страниц, чтение содержимого страницы, поиск по CQL.

**Ключевые результаты:**
- Конвертер `storage-to-md.ts` — turndown + плагин GFM + кастомные правила для ac:link, ri:page
- `confluence_list_spaces` — возвращает массив `{key, name, id}`
- `confluence_list_pages` — возвращает страницы пространства с пагинацией
- `confluence_read_page` — возвращает содержимое страницы в Markdown с метаданными
- `confluence_search` — принимает CQL-запрос, возвращает результаты в Markdown

**Smoke-тест:** Попросить LLM «Найди страницу про архитектуру в Confluence» — агент вызывает search/read_page и возвращает Markdown-содержимое.

### Этап 3: Write

Реализация инструментов для записи данных в Confluence. Конвертация Markdown в Confluence Storage Format через `marked` с кастомным renderer. Два инструмента: создание и обновление страниц. Slash-команда `/confluence` для диагностики и настройки.

**Ключевые результаты:**
- Конвертер `md-to-storage.ts` — marked + кастомный renderer (заголовки, списки, таблицы, код, ссылки, жирный/курсивный)
- `confluence_create_page` — принимает Markdown, создаёт страницу в настроенном пространстве, опционально под родителем
- `confluence_update_page` — обновляет содержимое существующей страницы по ID
- Команда `/confluence` — выводит статус подключения, конфигурацию, тестовые вызовы

**Smoke-тест:** Попросить LLM «Создай страницу "Отчёт" в Confluence с содержимым "Тестовый отчёт"» — страница появляется в пространстве.

### Этап 4: Polish

Улучшение качества: обработка ошибок с информативными сообщениями, edge cases (пустые результаты, длинные страницы, пагинация), кэширование результатов чтения в рамках сессии, документация расширения, подготовка к публикации в FAN Store.

**Ключевые результаты:**
- Обработка ошибок с рекомендациями для LLM (какие аргументы передать, примеры CQL)
- Пагинация с авто-подсказкой для LLM
- Кэш прочитанных страниц (по ID) в рамках сессии
- README.md расширения с инструкцией установки и настройки
- Подготовка пакета для FAN Store

**Smoke-тест:** Выполнить все 6 инструментов, включая сценарии с несуществующей страницей, пустым поиском, слишком длинным контентом.

## Риск-регистр

| Риск | Вероятность | Влияние | Митигация | Этап |
|------|:-----------:|:-------:|-----------|:----:|
| PAT не поддерживается в старой версии DC | Низкая | Высокое | Добавить fallback на Basic Auth в config.ts | 1 |
| Storage Format содержит неразбираемые макросы | Высокая | Среднее | Граничные правила turndown, fallback в plain text | 2 |
| Кастомный renderer marked не покрывает все Markdown-конструкции | Средняя | Среднее | Начать с базового подмножества, расширять по результатам | 3 |
| Rate limiting со стороны DC | Средняя | Низкое | Задержка между запросами, информирование LLM о лимитах | 4 |
| confluence.js несовместим с конкретной версией DC REST API | Низкая | Высокое | Проверить на этапе 1, подготовить fallback на прямой fetch | 1 |
| Большой документ (> 100 KB) вызывает таймаут | Низкая | Среднее | Streaming через `onUpdate`, настраиваемый timeout | 4 |

## Классификация приоритетов (MoSCoW)

### Must Have (обязательные этапы)
- Этап 1: foundation — без каркаса и подключения ничего не работает
- Этап 2: read — чтение — основная ценность для LLM-агента
- Этап 3: write — запись — completes двустороннюю интеграцию

### Should Have (настоятельно рекомендуемые)
- Этап 4: polish — качество, ошибки, кэширование критичны для повседневного использования

### Could Have (не входит в MVP)
- Работа с вложениями (загрузка/скачивание)
- Работа с комментариями
- Работа с лейблами
- Шаблоны документов

### Won't Have
- Поддержка Confluence Server (pre-DC)
- Создание и управление пространствами
- Конвертация ADF (Atlassian Document Format)
- Поддержка Confluence Cloud (может быть добавлена позже через тот же baseUrl)

## Критерии успеха фичи

- [ ] Все 6 инструментов (`confluence_list_spaces`, `confluence_list_pages`, `confluence_read_page`, `confluence_search`, `confluence_create_page`, `confluence_update_page`) работают на реальном экземпляре Confluence Data Center
- [ ] LLM-агент может прочитать страницу из Confluence и использовать полученный Markdown-контент в ответе
- [ ] LLM-агент может создать страницу в Confluence из Markdown-контента
- [ ] Конвертация Markdown↔Storage Format корректно обрабатывает: заголовки (h1-h6), списки (ul/ol), таблицы, блоки кода, жирный/курсивный текст, ссылки, изображения
- [ ] Операции чтения и записи выполняются менее чем за 10 секунд
- [ ] Расширение загружается в fan через auto-discovery без ошибок
- [ ] Команда `/confluence` показывает статус подключения и конфигурацию
- [ ] Обработка ошибок даёт LLM понятные рекомендации для исправления
