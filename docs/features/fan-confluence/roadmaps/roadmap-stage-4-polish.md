# Этап 4: Polish

## Метаданные
- **Номер этапа:** 4
- **Подветка:** feature/fan-confluence/stage-4-polish
- **Основная ветка:** feature/fan-confluence
- **Зависимости:** Этапы 1-3 (foundation, read, write) — все компоненты расширения
- **Результат этапа:** Расширение надёжно работает в production: корректная обработка ошибок, кэширование, информативные сообщения для LLM, документация

## Цель этапа

Улучшить качество и надёжность расширения: обработка ошибок с рекомендациями для LLM, кэширование результатов чтения, обработка edge cases, документация для пользователей, подготовка к публикации в FAN Store.

### Green — Реализация

- [ ] Обработать ошибки API во всех инструментах:
  - Общая функция `formatConfluenceError(error)` → `{ isError: true, content: [{ type: "text", text: "..." }], details: {} }`
  - Карта кодов ошибок → рекомендации на русском для LLM
  - 401 → «Проверьте CONFLUENCE_PAT в файле ~/.fan/agent/extensions/fan-confluence/.env»
  - 403 → «У текущего PAT нет доступа. Обратитесь к администратору Confluence.»
  - 404 → «Ресурс не найден. Проверьте page_id или spaceKey.»
  - 429 → «Превышен лимит запросов. Подождите и повторите.»

## Smoke-тесты этапа (обязательные)

| # | Проверка | Команда / Действие | Ожидаемый результат |
|---|----------|--------------------|---------------------|
| 1 | Несуществующая страница | Попросить LLM: «Прочитай страницу 999999 из Confluence» | Понятное сообщение «Страница не найдена, проверьте page_id» |
| 2 | Пустой поиск | Попросить LLM: «Найди XYZNOTEXIST123 в Confluence» | «По запросу ничего не найдено. Попробуйте изменить CQL-запрос.» |
| 3 | Кэширование | Прочитать страницу, затем прочитать её снова | Второй вызов мгновенный (из кэша) |
| 4 | Инвалидация кэша | Прочитать → обновить → прочитать ту же страницу | После обновления кэш инвалидирован, возвращается обновлённое содержимое |
