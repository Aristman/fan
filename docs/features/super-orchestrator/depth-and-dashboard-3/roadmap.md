## Фаза A «Глубина и границы»

**Цель:** Расширить рабочую глубину дерева до 3–4 уровней, ввести декларативные манифесты инструментов на каждый узел и обеспечить полную санитизацию всех межагентных сообщений. Все 3 функции фазы — модули расширения `fan-super-orchestrator` и изменения guard из этапа 2.
**Приоритет функций:** P0 (F-36, F-37), P1 (F-38)
**E2E-сценарий фазы:**
1. L0 порождает дерево глубины 3: L0 → 2×L1 → 2×L2 (каждый L1 порождает по L2) → каждый L2 получает пакет работ с `toolManifest: ["read","bash","grep"]` → L2 пытается вызвать `write` → отказ с диагностикой «tool 'write' not in manifest» → guard на глубине 4 разрешает порождение, на глубине 5 — отказ с эскалацией I3.
2. Миссия с манифестами: L0 отправляет пакет с `toolManifest: ["read","bash"]` → L1 выполняет задачу, используя только `read` и `bash` → попытка `write` отклонена sanitizer'ом → в `tree-journal.jsonl` записано событие `tool_blocked` с диагностикой.
**Smoke-критерий фазы:** Узел L2 порождается только в пределах глубины 4; на глубине 5 — отказ guard'а. Узел с манифестом `["read","bash"]` не может вызвать `write` — попытка отклонена с диагностикой. `npm run build` зелёный.

**Цель:** Реализовать Dashboard-компоненты для наблюдения за миссией в реальном времени (дерево узлов, статус, журнал, бюджет) и CLI-команду `fan mission tree <slug>`. Все 4 функции фазы — Lit-компоненты Dashboard и CLI-модуль.
**Приоритет функций:** P0 (F-42), P1 (F-39, F-40, F-47), P2 (F-41)
**E2E-сценарий фазы:**
1. Запущенная миссия глубины 2 (L0 → 3×L1) → Dashboard открывает страницу миссии → `<mission-tree>` отображает дерево узлов в реальном времени (обновление через WS `mission_event` с задержкой <5 сек) → `<mission-status>` показывает статус, итерацию, расход → `<mission-log>` отображает ленту событий (spawn, complete, fail) → `<mission-budget>` показывает столбчатую диаграмму расхода по веткам (L1/node-1: $0.45, L1/node-2: $0.30, L1/node-3: $0.12).
