## Метаданные

- **Дата:** 2026-06-20
- **Тип идеи:** Техническая
- **Глубина:** Стандартный
- **Статус:** Исследовано

## 1. Ядро идеи

> Сделать расширение для голосового ввода текста в TUI FAN, которое распознаёт речь через локальный whisper.cpp и опционально постобрабатывает результат через локальную или внешнюю Ollama-модель.

### Цель

Создать опциональное FAN-расширение, позволяющее пользователю в терминальном интерфейсе FAN диктовать текст: по нажатию горячей клавиши или команде расширение записывает аудио, распознаёт его и вставляет результат в строку ввода TUI. Если настроена Ollama-модель — распознанный текст дополнительно улучшается (пунктуация, исправление ошибок, структурирование) перед вставкой.

### Контекст

Пользователь уже получил базовый анализ голосового ввода как встроенной фичи FAN. Теперь рассматривается более узкая и независимая реализация в виде расширения: только для TUI, с двухэтапным pipeline «распознавание + постобработка», где постобработка делегирована Ollama.

## 2. Исследование

### 2.1 Проблема и аудитория

**Проблема:** Ввод длинных промптов и сообщений в TUI FAN требует ручного набора, что замедляет работу и неудобно при отсутствии полноценной клавиатуры.

**Для кого:** Пользователи FAN, предпочитающие терминальный интерфейс и желающие использовать голос для набора текста.

**Насколько острая:** Средняя. Это UX-улучшение, а не критическая функция. Встроенный ручной ввод остаётся fallback'ом.

### 2.2 Текущее состояние

FAN имеет зрелое API расширений:

- `fan.registerCommand()` и `fan.registerShortcut()` — для активации голосового ввода.
- `ctx.ui.custom()` — для показа кастомного UI (индикатор записи, loader).
- `ctx.ui.setEditorText()` — для вставки распознанного текста в строку ввода TUI.
- `fan.exec()` — для запуска внешних команд (`sox`, `ffmpeg`, `whisper.cpp`).

Пример `examples/extensions/qna.ts` демонстрирует похожий паттерн: команда → loader → LLM-вызов → `setEditorText()`.

### 2.3 Источники исследования

| Источник | Релевантность | Ключевые выводы |
|----------|---------------|-----------------|
| Документация FAN — Extensions (`packages/coding-agent/docs/extensions.md`) | Высокая | Расширения могут регистрировать команды, шорткаты, инструменты, взаимодействовать с TUI через `ctx.ui`, выполнять внешние команды через `fan.exec()`. |
| Пример `qna.ts` (`packages/coding-agent/examples/extensions/qna.ts`) | Высокая | Показывает паттерн: команда → кастомный UI с loader → LLM-вызов → `ctx.ui.setEditorText()`. |
| Ollama API (`github.com/ollama/ollama/blob/main/docs/api.md`) | Высокая | Endpoint `/api/chat` принимает текстовые сообщения и поддерживает структурированный вывод (`format`). Аудио-вход в API пока не задокументирован. |
| Ollama Audio models (`ollama.com/search?c=audio`) | Средняя | Есть модели с тегом `audio` (gemma4, nemotron3), но их страницы и API-интеграция пока ориентированы на текст/изображения; аудио-вход нестабилен. |
| GitHub — whisper.cpp (`github.com/ggerganov/whisper.cpp`) | Высокая | Зрелый локальный движок распознавания речи. Модель `base` занимает ~142 МБ, поддерживает много языков, есть CLI. |

## 3. SWOT-анализ

### Strengths (Сильные стороны) 🔵

- **Изоляция от ядра FAN.** Расширение не требует изменений в пакетах `coding-agent`, `tui`, `api-gateway`. Обновления и отладка не затрагивают основной продукт.
- **Повторно используемые паттерны.** `qna.ts` уже показывает, как делать LLM-вызов и вставлять результат в редактор. Нужно заменить LLM-вызов на локальное распознавание + опциональный Ollama.
- **Гибкость конфигурации.** Пользователь сам выбирает модель Ollama, базовый URL и включена ли постобработка. При отсутствии Ollама расширение работает как чистый голосовой ввод.
- **Локальность данных.** whisper.cpp и Ollama работают локально (или на указанном пользователем сервере); аудио не отправляется в сторонние облака.
- **Лёгкость распространения.** Расширение можно опубликовать в FAN Store и установить через `fan store install voice-ollama-tui`.

### Weaknesses (Слабые стороны) 🟠

- **Зависимость от внешних инструментов.** Для записи аудио нужны `sox`, `arecord` или `ffmpeg`; для распознавания — `whisper.cpp`. Установка этих зависимостей ложится на пользователя.
- **Кросс-платформенная запись аудио.** Терминал не имеет единого API микрофона; на Windows, macOS и Linux используются разные утилиты.
- **Двойная задержка.** Сначала распознавание whisper.cpp, затем POST-запрос к Ollama. Даже на быстрых машинах это занимает секунды.
- **Ollama должна быть запущена.** Если пользователь выбрал постобработку через Ollama, нужен работающий сервер `ollama serve`.

### Opportunities (Возможности) 🟢

- **Расширение может стать основой для голосовых команд.** После появления аудиоинфраструктуры можно добавить режимы: «диктовка», «голосовая команда», «быстрая заметка».
- **Переиспользование whisper-моделей.** Если в FAN позже появится встроенный голосовой ввод, расширение может стать прототипом или совместно использовать кэш моделей.
- **Интеграция с Ollama как провайдером.** FAN уже поддерживает кастомных провайдеров; расширение может не только постобрабатывать текст, но и автоматически регистрировать Ollama как источник моделей.

### Threats (Угрозы) 🔴

- **Изменения в API Ollama.** Аудио-поддержка в Ollama находится в ранней стадии; если в будущем появится нативный аудио-вход, текущая архитектура whisper+Ollama может устареть.
- **Сложности с правами доступа к микрофону.** В некоторых терминальных эмуляторах и ОС доступ к микрофону для CLI-процессов ограничен.
- **Низкий интерес пользователей.** TUI — узкая аудитория; многие предпочтут веб-дашборд или ручной ввод.

## 4. Альтернативы

### 4.1 Альтернатива: Расширение только с whisper.cpp (без Ollama)

**Суть:** Расширение записывает аудио, вызывает whisper.cpp и сразу вставляет распознанный текст. Без постобработки.

**Плюсы:**
- Минимум зависимостей.
- Максимальная скорость.
- Простая конфигурация.

**Минусы:**
- Распознанный текст может содержать ошибки, не хватать пунктуации.
- Нет возможности адаптировать результат под контекст FAN.

| Параметр | Оценка |
|----------|--------|
| Сложность | Низкая |
| Время | 1–2 дня |
| Риски | Низкие |

### 4.2 Альтернатива: Расширение с whisper.cpp + Ollama-постобработкой (рекомендуемая)

**Суть:** Расширение распознаёт аудио через whisper.cpp, затем отправляет текст в Ollama с системным промптом для улучшения. Если Ollama недоступна — вставляет сырой текст.

**Плюсы:**
- Высокое качество итогового текста.
- Гибкость: пользователь выбирает модель и может отключить постобработку.
- Соответствует исходной идее пользователя.

**Минусы:**
- Требуется запущенная Ollama.
- Двойная задержка.
- Больше кода и настроек.

| Параметр | Оценка |
|----------|--------|
| Сложность | Средняя |
| Время | 3–5 дней |
| Риски | Средние |

### 4.3 Альтернатива: Расширение с прямой отправкой аудио в Ollama

**Суть:** Аудиофайл напрямую передаётся в Ollama-модель с поддержкой аудио (например, gemma4 E2B/E4B или nemotron3).

**Плюсы:**
- Один этап вместо двух.
- Потенциально лучшее понимание контекста и произношения.

**Минусы:**
- Ollama API для аудио-входа пока не задокументирован и нестабилен.
- Поддерживаемые модели огромны (7–28 ГБ) и требуют мощного железа.
- gemma4 E2B/E4B с аудио не представлены в списке тегов на ollama.com; доступны только dense-варианты без аудио.
- Высокий риск, что реализация сломается при обновлении Ollama.

| Параметр | Оценка |
|----------|--------|
| Сложность | Высокая |
| Время | 5–10 дней |
| Риски | Высокие |

### 4.4 Альтернатива: Ничего не делать

**Суть:** Оставить голосовой ввод за пределами TUI; пользователи продолжают набирать текст вручную.

**Плюсы:**
- Нулевые затраты.
- Нет дополнительных зависимостей.

**Минусы:**
- FAN отстаёт от пользовательских ожиданий.
- Упускается возможность протестировать голосовой ввод в изолированном расширении.

| Параметр | Оценка |
|----------|--------|
| Сложность | Низкая |
| Время | 0 |
| Риски | Низкие |

## 6. Рекомендация

### Что делать: Расширение «whisper.cpp + опциональная Ollama-постобработка» для TUI

**Уверенность:** 0.88/1.0

**Обоснование:**

1. **Расширение — правильный уровень абстракции.** Идея не требует изменений в ядре FAN; её можно реализовать, протестировать и распространить независимо. Это снижает риск для основного продукта и позволяет быстро итерироваться.
2. **Паттерн уже проверен.** Пример `qna.ts` показывает, как делать команду → loader → LLM-вызов → `setEditorText()`. Наш pipeline отличается только источником данных: аудио → whisper.cpp вместо текста → `complete()`.
3. **Ollama для постобработки — стабильный и гибкий вариант.** Endpoint `/api/chat` Ollama хорошо документирован, поддерживает локальные и удалённые серверы, позволяет настраивать модель и системный промпт. Это соответствует требованию пользователя о настраиваемой модели.
4. **Прямая передача аудио в Ollama пока рискованна.** API для аудио-входа не задокументирован, доступные аудио-модели тяжёлые и нестабильны. Игнорируем этот путь на текущем этапе.
5. **Fallback сохраняет работоспособность.** Если Ollama не настроена или недоступна, расширение всё равно выполняет базовое распознавание и вставляет текст.

**Компромиссы:**

- **Принимаем:** Двухэтапная задержка (whisper.cpp + Ollama) в обмен на качество и гибкость.
- **Принимаем:** Необходимость установки внешних зависимостей (`whisper.cpp`, аудиоутилиты, Ollama).
- **Принимаем:** Реализация только для TUI, без Web и API (как запросил пользователь).
- **Отклоняем:** Прямая отправка аудио в Ollama — слишком высокие технические риски и неясная поддержка.
- **Отклоняем:** Встроенная фича в ядре FAN — избыточно для экспериментальной функции; расширение быстрее и безопаснее.

**Предупреждения:**

- ⚠️ **Запись аудио в терминале — самый непредсказуемый компонент.** Нужен прототип на Linux/macOS/Windows.
- ⚠️ **Постобработка может изменить смысл.** Рекомендуется сначала показывать результат пользователю или делать постобработку консервативной.
- ⚠️ **Размер whisper-моделей.** Необходимо решить, скачивать ли модель автоматически или требовать ручной установки.

#### Стек технологий

| Компонент | Технология | Обоснование |
|-----------|------------|-------------|
| Расширение FAN | TypeScript, `@seaagents/fan-coding-agent` | Стандартный способ расширения TUI и команд. |
| Запись аудио | `sox`, `arecord`, `ffmpeg` | Кросс-платформенные CLI-утилиты для записи с микрофона. |
| Распознавание речи | `whisper.cpp` CLI | Локальный, мультиязычный, MIT-лицензия. |
| Постобработка | Ollama `/api/chat` | Гибкая локальная/удалённая модель для улучшения текста. |
| Вставка в TUI | `ctx.ui.setEditorText()` | Прямой способ установить текст в строку ввода FAN. |
| UI статуса | `ctx.ui.custom()` + loader | Индикатор записи и обработки. |

#### Конфигурация

```typescript
interface VoiceOllamaConfig {
  // Аудио
  audioDevice?: string;        // Имя устройства записи
  recordDuration?: number;     // Максимальная длительность записи (сек)
  audioFormat?: "wav" | "flac"; // Формат записи

  // Whisper
  whisperBinPath?: string;     // Путь к whisper.cpp CLI
  whisperModelPath?: string;   // Путь к ggml-модели
  whisperLanguage?: string;    // Язык распознавания, например "ru"

  // Ollama
  ollamaEnabled?: boolean;     // Включить постобработку
  ollamaBaseUrl?: string;      // http://localhost:11434
  ollamaModel?: string;        // например, "llama3.2"
  ollamaSystemPrompt?: string; // Промпт для улучшения текста
}
```

Пример `.env` или конфигурационного файла расширения:

```ini
WHISPER_MODEL_PATH=~/.fan/models/speech/ggml-base.bin
WHISPER_LANGUAGE=ru
OLLAMA_ENABLED=true
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=llama3.2
OLLAMA_SYSTEM_PROMPT="Исправь пунктуацию и опечатки, сохранив исходный смысл. Не добавляй пояснений."
```

#### Поток данных

1. Пользователь нажимает `/voice` или `Ctrl+Shift+V` (настраиваемый шорткат).
2. Расширение показывает overlay с индикатором записи.
3. Запускается запись аудио во временный файл (например, `/tmp/fan-voice-<id>.wav`).
4. По нажатию Enter/Escape или по таймауту запись завершается.
5. Аудио конвертируется в WAV 16 кГц моно, если нужно.
6. Вызывается `whisper.cpp` CLI: `whisper-cli -m <model> -l <lang> -f <audio>`.
7. Если `ollamaEnabled === true`, распознанный текст отправляется в Ollama `/api/chat`.
8. Итоговый текст устанавливается в редактор через `ctx.ui.setEditorText()`.

#### Пример вызова Ollama

```typescript
const response = await fetch(`${config.ollamaBaseUrl}/api/chat`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    model: config.ollamaModel,
    messages: [
      { role: "system", content: config.ollamaSystemPrompt },
      { role: "user", content: rawTranscript },
    ],
    stream: false,
    options: { temperature: 0.2 },
  }),
});

const data = await response.json();
const improvedText = data.message.content;
```

### 8.2 Оценка трудозатрат

| Задача | Сложность | Оценка времени | Зависимости |

| Структура расширения и конфиг | Низкая | 2–3 ч | — |
| Запись + распознавание + вставка | Средняя | 6–8 ч | Спайки |

| Тестирование на платформах | Средняя | 4–6 ч | Всё выше |
| Документация | Низкая | 2–3 ч | Тестирование |

**Итого:** ~26–37 часов (~4–5 рабочих дней).

**MVP (whisper.cpp без Ollama):** ~14–18 часов (~2 рабочих дня).

### 8.3 Adoption / план внедрения

#### Шаги внедрения

1. Разработать расширение в директории `~/.fan/agent/extensions/voice-ollama-tui/`.
2. Протестировать на Linux, macOS и Windows (WSL/Git Bash).
3. Опубликовать в FAN Store как `voice-ollama-tui`.
4. Установить через `fan store install voice-ollama-tui`.
5. При первом запуске предложить скачать whisper-модель и проверить зависимости.

#### Rollback-стратегия

- Расширение полностью опционально: удаление директории или `fan store remove voice-ollama-tui` отключает функцию.
- При ошибке на любом этапе расширение показывает уведомление и не портит состояние TUI.
- Если whisper.cpp недоступен, команда `/voice` сообщает об этом и даёт инструкции.
