# Голосовой ввод текста в FAN — исследование идеи

## Метаданные

- **Дата:** 2026-06-20
- **Тип идеи:** Техническая
- **Глубина:** Стандартный
- **Статус:** Исследовано

---

## 1. Ядро идеи

> Реализовать в проекте голосовой ввод текста.

### Цель

Дать пользователям FAN возможность диктовать текстовые сообщения вместо ручного набора во всех точках взаимодействия: веб-дашборде, терминальном интерфейсе (TUI) и через внешнее API.

### Контекст

FAN — локальный инструмент для разработчиков с тремя клиентскими поверхностями. Голосовой ввод снизит трение при вводе длинных промптов и повысит доступность интерфейса. Пользователь поставил жёсткие ограничения: данные не должны покидать устройство, приоритет отдаётся решениям с открытым исходным кодом, базового качества распознавания достаточно.

## 2. Исследование

### 2.1 Проблема и аудитория

**Проблема:** Ввод длинных текстовых запросов вручную в TUI и веб-дашборде занимает время и неудобен на устройствах без полноценной клавиатуры.

**Для кого:** Пользователи FAN, которые работают с агентом через TUI, веб-дашборд или внешние интеграции.

**Насколько острая:** Средняя. Это улучшение UX, а не блокирующая функция. Без него пользователи продолжат набирать текст вручную.

### 2.2 Текущее состояние

В кодовой базе FAN нет готовых компонентов для работы с аудио или распознаванием речи. Инфраструктура для добавления нового API-эндпоинта и UI-компонента присутствует:

- `packages/api-gateway/src/http-server.ts` — Hono-сервер с авторизацией и REST-маршрутами.
- `packages/dashboard/src/components/chat-view.ts` — компонент чата с текстовым полем ввода.
- `packages/tui/src/components/input.ts` — однострочный ввод в терминале.

### 2.3 Источники исследования

| Источник | Релевантность | Ключевые выводы |

## 3. SWOT-анализ

### Strengths (Сильные стороны) 🔵

- **Локальность из коробки.** FAN уже работает на машине пользователя, поэтому локальное распознавание через `whisper.cpp` не нарушает приватность и не требует облака.
- **Единая серверная обработка.** Если аудио с веб-клиента отправляется на локальный сервер FAN, можно использовать один движок распознавания для Web, TUI и API.
- **Зрелая экосистема.** `whisper.cpp` имеет MIT-лицензию, активное сообщество, готовые CLI, Docker-образы и примеры для многих платформ.
- **Мультиязычность.** Whisper обучен на 99 языках; базовая модель подходит для русского, английского и других языков.

### Weaknesses (Слабые стороны) 🟠

- **Запись аудио в TUI — нетривиальная задача.** Терминал не имеет стандартного API микрофона; придётся вызывать внешние утилиты (`sox`, `arecord`, `ffmpeg`) или нативные модули.
- **Размер моделей.** Модель `base` добавляет ~142 МБ к дистрибутиву или требует скачивания при первом запуске.
- **Задержка при первом запуске.** Загрузка модели в память занимает время; пользователь будет ждать перед первым распознаванием.
- **Зависимость от разрешений.** Браузер и операционная система запрашивают доступ к микрофону; в TUI нужны корректные аудиоустройства.

### Opportunities (Возможности) 🟢

- **Переиспользование инфраструктуры ModelManager.** Можно управлять моделями распознавания так же, как моделями для генерации текста: выбор модели, путь к файлу, обновления.
- **Голосовые команды в TUI.** После появления аудиоинфраструктуры можно добавить голосовые сочетания клавиш или команды (например, «запланировать задачу»).
- **Улучшение доступности.** Голосовой ввод помогает пользователям с ограниченными возможностями и тем, кто работает без клавиатуры.

### Threats (Угрозы) 🔴

- **Кросс-платформенная запись аудио.** Разные ОС (Windows, Linux, macOS) требуют разных утилит записи и путей к устройствам.
- **Рост размера дистрибутива.** Включение модели в поставку увеличит размер установочного пакета FAN.
- **Конкуренты.** Другие инструменты для разработки (Claude Code, Cursor, Copilot) активно добавляют голосовой ввод; отсутствие фичи может снизить привлекательность FAN.
- **Не все пользователи имеют микрофон.** Функция останется опциональной, что ограничивает её влияние на retention.

## 4. Альтернативы

### 4.1 Альтернатива: Единый серверный движок на базе whisper.cpp

**Суть:** Все клиенты (Web, TUI, API) записывают аудио и отправляют его на локальный сервер FAN. Сервер вызывает `whisper.cpp` (CLI или нативный биндинг) и возвращает текст.

**Плюсы:**
- Один движок для всех интерфейсов.
- Высокое качество распознавания на многих языках.
- Данные не покидают устройство.
- Простая интеграция через CLI-обёртку.

**Минусы:**
- Увеличение размера дистрибутива.
- Задержка при передаче аудио и инициализации модели.
- Требуется управление моделями и их скачивание.

| Параметр | Оценка |
|----------|--------|
| Сложность | Средняя |
| Время | 3–5 дней |
| Риски | Средние |

### 4.2 Альтернатива: Единый серверный движок на базе Vosk

**Суть:** Аналогично whisper.cpp, но вместо Whisper используется лёгкий движок Vosk с моделями ~50 МБ.

**Плюсы:**
- Модели меньше и загружаются быстрее.
- Низкое потребление ресурсов.
- Есть Node.js-биндинги.

**Минусы:**
- Качество распознавания уступает Whisper, особенно для русского и технических терминов.
- Меньше языков и менее активное сообщество.
- Слабее справляется с длинными диктовками.

| Параметр | Оценка |
|----------|--------|
| Сложность | Средняя |
| Время | 3–4 дня |
| Риски | Средние |

### 4.3 Альтернатива: Гибрид Web Speech API + серверный whisper.cpp

**Суть:** В веб-дашборде используется Web Speech API (по умолчанию облачный, с fallback к локальному серверу FAN), в TUI/API — только серверный whisper.cpp.

**Плюсы:**
- В Web не требуется передавать аудио на сервер, если сработает локальное распознавание.
- Быстрый путь для MVP в браузере.

**Минусы:**
- Два разных движка распознавания = двойная поддержка и несогласованное поведение.
- Web Speech API по умолчанию отправляет данные в облако, что нарушает требование приватности.
- Локальный режим Web Speech API поддерживается ограниченно (в основном Chrome с загруженными языковыми пакетами).

| Параметр | Оценка |
|----------|--------|
| Сложность | Высокая |
| Время | 5–7 дней |
| Риски | Высокие |

### 4.4 Альтернатива: Ничего не делать

**Плюсы:**

- Нет увеличения размера дистрибутива.

**Минусы:**
- FAN отстаёт от конкурентов.
- Теряется улучшение UX для длинных промптов.

| Параметр | Оценка |

| Риски | Низкие |

## 6. Рекомендация

### Что делать: Единый серверный движок на базе whisper.cpp

**Уверенность:** 0.85/1.0

**Обоснование:**

1. **Один движок для всех интерфейсов.** Web-клиент записывает аудио через `MediaRecorder` и отправляет его на локальный сервер FAN; TUI записывает аудио через внешние утилиты; API принимает аудиопоток. Все они используют один сервис распознавания.
2. **Соответствие ограничениям.** `whisper.cpp` работает локально, имеет открытый исходный код и MIT-лицензию; данные не покидают устройство.
3. **Достаточное качество.** Для базового качества подходит модель `base` (~142 МБ на диске); при необходимости можно перейти на `small` (~466 МБ).
4. **Мультиязычность.** Whisper поддерживает русский, английский и десятки других языков, что соответствует требованию «несколько языков».
5. **Простота интеграции.** Первый вариант можно реализовать через вызов CLI `whisper.cpp` без сложных нативных биндингов.

**Компромиссы:**

- **Принимаем:** Web-распознавание происходит не в браузере, а на локальном сервере FAN. Данные при этом не уходят за пределы устройства, поэтому требование приватности сохраняется.
- **Принимаем:** Увеличение размера дистрибутива или необходимость скачивать модель при первом запуске.
- **Отклоняем:** Web Speech API в облачном режиме — нарушает требование приватности.
- **Отклоняем:** Vosk как основной движок — качество ниже, а трудозатраты сопоставимы с whisper.cpp.

**Предупреждения:**

- ⚠️ **TUI — самый рискованный компонент.** Перед полноценной реализацией нужен прототип записи аудио в терминале на целевых платформах.
- ⚠️ **Размер модели.** Необходимо решить, включать ли модель в дистрибутив или скачивать при первом использовании.
- ⚠️ **Производительность на CPU.** На слабых машинах распознавание может занимать несколько секунд; стоит предусмотреть индикатор процесса.

## 8. Специфичные разделы

### 8.1 Техническая архитектура

#### Архитектура

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   Web Dashboard │     │      TUI        │     │  External API   │
│  (MediaRecorder)│     │ (sox/arecord)   │     │  (audio file)   │
└────────┬────────┘     └────────┬────────┘     └────────┬────────┘
         │                       │                       │
         │     audio blob        │     audio file        │   audio file
         └───────────────────────┼───────────────────────┘
                                 ▼
                    ┌─────────────────────┐
                    │   FAN API Gateway   │
                    │ /api/speech/transcribe
                    └──────────┬──────────┘
                               ▼
                    ┌─────────────────────┐
                    │ SpeechRecognitionService
                    │   (whisper.cpp CLI) │
                    └──────────┬──────────┘
                               ▼
                    ┌─────────────────────┐
                    │   Whisper model     │
                    │   (base/small)      │
                    └─────────────────────┘
```

#### Стек технологий

| Компонент | Технология | Обоснование |
|-----------|------------|-------------|
| Движок распознавания | `whisper.cpp` CLI | Локальное выполнение, MIT-лицензия, мультиязычность, зрелость. |
| Серверный API | Hono в `packages/api-gateway` | Уже используется в FAN; легко добавить новый маршрут. |
| Web-запись | `MediaRecorder` + `getUserMedia` | Стандартные браузерные API, работают во всех современных браузерах. |
| TUI-запись | `sox` / `arecord` / `ffmpeg` | Кросс-платформенный способ записи аудио из терминала. |
| Формат аудио | WAV 16 кГц, 16 бит, моно | Требование `whisper.cpp` для входных данных. |
| Кэш моделей | `~/.fan/models/speech/` | Единое место хранения, как и для других моделей FAN. |

#### Интеграция

- Новый endpoint `/api/speech/transcribe` принимает multipart/form-data с аудиофайлом и опциональным параметром `lang`.
- `SpeechRecognitionService` сохраняет файл во временную директорию, конвертирует при необходимости в WAV 16 кГц моно, вызывает `whisper.cpp` CLI, возвращает текст.
- В `chat-view` добавляется кнопка рядом с полем ввода; при нажатии запускается/останавливается запись, после остановки аудио отправляется на endpoint, распознанный текст вставляется в поле ввода.
- В TUI добавляется горячая клавиша для записи; процесс записи отображается индикатором; по завершении аудио отправляется на тот же endpoint.

#### API / Интерфейсы

```typescript
// Запрос: multipart/form-data
// Поля:
//   audio: Blob (audio/webm или audio/wav)
//   lang?: string (например, "ru", "en")

// Ответ: 200 OK
interface TranscribeResponse {
  text: string;
  language?: string;
  duration?: number;
}

// Ответ при ошибке: 4xx/5xx
interface TranscribeError {
  error: string;
  code: string;
}
```

| Документация | Низкая | 2–4 ч | Тестирование |

**Итого:** ~30–44 часа (~4–6 рабочих дней).

**MVP (Web + endpoint, без TUI):** ~16–20 часов (~2–3 рабочих дня).

### 8.3 Adoption / план внедрения

#### Шаги внедрения

1. Включить `whisper.cpp` как опциональную зависимость или инструкцию по установке.
2. При первом вызове распознавания скачать модель `base` в `~/.fan/models/speech/`, если она отсутствует.
3. Добавить фичу за флагом конфигурации (например, `enableVoiceInput: true`).
4. Обновить `fan doctor` для проверки наличия `whisper.cpp` и аудиоутилит.

#### Rollback-стратегия

- Фича полностью опциональна: если `whisper.cpp` недоступен, кнопка микрофона скрывается, а endpoint возвращает ошибку `SPEECH_NOT_CONFIGURED`.
- Модель хранится отдельно от основного дистрибутива; удаление папки `~/.fan/models/speech/` откатывает фичу к состоянию «не установлено».
