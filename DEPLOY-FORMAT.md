# DEPLOY.toml — Манифест деплоя пакетов

> Версия схемы: **1** · Формат: TOML · Расположение: корень пакета

`DEPLOY.toml` определяет, какие файлы включаются в дистрибутивный архив FAN Store, какие всегда исключаются, и какие файлы на стороне клиента должны сохраниться при обновлениях без перезаписи.

---

## Краткая справка

| Секция | Ключ | Тип | Обязательно | Назначение |
|--------|-----|------|-------------|-----------|
| `[package]` | `name` | string | ✅ | Идентификатор пакета (совпадает с именем в `package.json`) |
| `[package]` | `type` | `"extension"` \| `"skill"` \| `"theme"` \| `"bundle"` | ✅ | Тип пакета — определяет поведение при установке |
| — | `include` | string[] | ✅ | Glob-паттерны файлов для **упаковки в архив** |
| — | `exclude` | string[] | ✅ | Glob-паттерны, **переопределяющие include** — никогда не упаковываются |
| — | `preserve` | string[] | ✅ | Файлы, которые клиент **не должен перезаписывать** при обновлениях |

> Все три массива должны присутствовать. Для пустых секций используйте `[]`.

---

## Обзор

### Что это такое

`DEPLOY.toml` — манифест деплоя, размещаемый в корне директории каждого пакета FAN Store. Служит декларативным контрактом между автором пакета и пайплайном сборки/упаковки.

### Зачем он нужен

- **Детерминированные архивы** — один и тот же `DEPLOY.toml` всегда даёт одинаковый набор файлов, независимо от того, кто запускает сборку.
- **Безопасность обновлений** — правила `preserve` защищают конфигурацию пользователя (API-ключи, локальные настройки) от перезаписи при обновлении пакета.
- **Типо-ориентированная упаковка** — разные типы пакетов (расширения, скиллы, бандлы) имеют разную структуру файлов; манифест делает ожидания явными.

### Когда используется

| Этап | Как используется `DEPLOY.toml` |
|------|-------------------------------|
| **Сборка** | Определяет, какие файлы попадают в архив `.tar.gz` |
| **Публикация** | Архив загружается в репозиторий FAN Store |
| **Установка** | Клиент извлекает архив в директорию расширений/скиллов |
| **Обновление** | Правила `preserve` защищают локальные файлы от перезаписи |

## Спецификация схемы v1

### Заголовок файла

Каждый `DEPLOY.toml` начинается с блока комментариев, идентифицирующего формат:

```toml
# DEPLOY.toml — FAN Package Deployment Manifest
# Schema version: 1
```

### Секция `[package]`

```toml
[package]
name = "my-extension"
type = "extension"
```

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | string | Идентификатор пакета. Должен совпадать с полем `name` в `package.json`. Используется как имя top-level директории внутри архива `.tar.gz`. |
| `type` | enum | Одно из: `extension`, `skill`, `theme`, `bundle`. Определяет, как клиент устанавливает и загружает пакет. |

### `include` — Файлы для упаковки

```toml
include = [
    "index.ts",
    "src/**/*.ts",
    "package.json",
    "README.md",
]
```

Массив glob-паттернов. Файлы, совпадающие **хотя бы с одним** паттерном include, являются кандидатами на упаковку. Паттерны оцениваются относительно корневой директории пакета.

**Правила:**
- Необходим хотя бы один паттерн для непустого архива.
- В паттернах используются прямые слеши (`/`) на всех платформах.
- Поддерживаются как буквальные имена файлов, так и glob-подстановки.

### `exclude` — Паттерны переопределения

```toml
exclude = [
    "node_modules/",
    "*.test.ts",
    ".env",
]
```

Массив glob-паттернов. Любой файл, совпадающий с паттерном exclude, **никогда не упаковывается**, даже если он также совпадает с паттерном include. Exclude всегда имеет приоритет.

**Правила:**
- Должен присутствовать (используйте `[]`, если исключать нечего).
- Оценивается после `include` — действует как фильтр.
- Паттерны директорий должны заканчиваться на `/` или использовать `**` для рекурсивного совпадения.

### `preserve` — Защита файлов на стороне клиента

```toml
preserve = [
    "config.json",
    ".env",
]
```

Массив путей к файлам (относительно директории установки пакета), которые клиент **не должен перезаписывать** при обновлении уже установленного пакета.

**Правила:**
- Должен присутствовать (используйте `[]`, если сохранять нечего).
- Это **пути в директории установки**, а не glob-паттерны — они ссылаются на файлы, которые существуют на машине пользователя после установки.
- Типичное применение: изменённые пользователем конфигурационные файлы, локальные секреты (`.env`).
- При первой установке правила preserve не действуют (нет существующих файлов для защиты).

## Синтаксис glob-паттернов

FAN использует стандартные glob-паттерны для `include` и `exclude`:

| Паттерн | Совпадает с | Пример |
|---------|-------------|--------|
| `*` | Любые символы, кроме `/` | `*.ts` → `index.ts`, `config.ts` (но не `src/index.ts`) |
| `**` | Любые символы, включая `/` (рекурсивно) | `src/**/*.ts` → `src/a.ts`, `src/deep/b.ts` |
| `?` | Один символ, кроме `/` | `file?.ts` → `file1.ts` |
| `[abc]` | Класс символов | `file[12].ts` → `file1.ts`, `file2.ts` |

### Распространённые паттерны

| Паттерн | Значение |
|---------|----------|
| `*.ts` | Все TypeScript-файлы только в текущей директории |
| `**/*.ts` | Все TypeScript-файлы в любом месте дерева |
| `src/**/*.ts` | Все TypeScript-файлы внутри `src/` |
| `agents/*.md` | Markdown-файлы непосредственно в `agents/` |
| `references/**/*.md` | Markdown-файлы в `references/` и всех поддиректориях |
| `node_modules/` | Сама директория `node_modules` |
| `**/node_modules/**` | Любая директория `node_modules` на любой глубине (для бандлов) |

### Подводные камни

1. **`*.ts` не рекурсивен.** Совпадает только с файлами в текущей директории. Используйте `**/*.ts` для рекурсивного совпадения.

2. **Паттерны директорий требуют `/**` для содержимого.** `"dist/"` совпадает с самой записью директории. Чтобы исключить всё содержимое, используйте `"dist/**"` или `"dist/"` (большинство реализаций трактуют завершающий `/` как рекурсивный).

3. **`.env.*` ловит `.env.example`.** Если вы включили `.env.example`, но исключили `.env.*`, файл-пример будет исключён. Используйте явные имена:
   ```toml
   # ❌ Неправильно — .env.example тоже исключается
   include = [".env.example"]
   exclude = [".env.*"]

   # ✅ Правильно — явные паттерны не конфликтуют
   include = [".env.example"]
   exclude = [".env", ".env.local", ".env.development"]
   ```

4. **Только прямые слеши.** В паттернах всегда используйте `/`, даже в Windows.

## Паттерны по типам пакетов

### Расширения (Extensions)

Расширения — это TypeScript-пакеты (или скомпилированный JavaScript), которые интегрируются в рантайм FAN.

**Дистрибуция скомпилированного JS** (наиболее распространена для опубликованных пакетов):

```toml
include = [
    "*.js",
    "*.d.ts",
    "agents/*.js",
    "agents/*.d.ts",
    "agents/*.md",
    "prompts/*.md",
    "package.json",
    "README.md",
    "config.example.json",
]
```

**Дистрибуция исходников TypeScript** (для пакетов, которые транспилируются на клиенте):

```toml
include = [
    "src/**/*.ts",
    "tsconfig.json",
    "package.json",
    "README.md",
]
```

**Однофайловые расширения** (простые расширения с плоской структурой):

```toml
include = [
    "index.ts",
    "config.ts",
    "types.ts",
    "tools/*.ts",
    "package.json",
    "README.md",
]
```

### Скиллы (Skills)

Скиллы — это чистые markdown-пакеты: файл `SKILL.md` с опциональными справочными документами и скриптами.

**Минимальный скилл:**

```toml
include = [
    "SKILL.md",
    "package.json",
]

exclude = []
preserve = []
```

**Скилл со справочниками и скриптами:**

```toml
include = [
    "SKILL.md",
    "package.json",
    "README.md",
    "references/**/*.md",
    "scripts/**/*.sh",
    "templates/**/*",
]

exclude = []
preserve = []
```

> Скиллы никогда не нуждаются в `exclude` или `preserve` — это read-only markdown без генерируемых файлов или клиентского состояния.

### Темы (Themes)

Темы — это однофайловые JSON-пакеты (`theme.json`).

```toml
[package]
name = "my-theme"
type = "theme"

include = [
    "theme.json",
    "package.json",
    "README.md",
]

exclude = []
preserve = []
```

### Бандлы (Bundles)

Бандлы содержат вложенные пакеты (расширения + скиллы + темы) в одном архиве. Все glob-паттерны должны использовать префиксы `**/` для совпадения на любой глубине.

```toml
[package]
name = "my-bundle"
type = "bundle"

include = [
    "package.json",
    "README.md",
    "extensions/**/*.ts",
    "extensions/**/package.json",
    "extensions/**/*.md",
    "extensions/**/config.example.json",
    "skills/**/SKILL.md",
    "skills/**/package.json",
]

exclude = [
    "**/node_modules/**",
    "**/.env*",
    "**/*.test.*",
    "**/*.spec.*",
    "**/dist/**",
    "**/__tests__/**",
]

preserve = []
```

> Паттерны бандлов имеют префикс `**/`, потому что директории вложенных пакетов могут находиться на любой глубине внутри структуры бандла.

## Стандартные правила exclude

Большинство расширений используют общий набор паттернов exclude. Скопируйте этот блок как отправную точку:

```toml
exclude = [
    # Зависимости
    "node_modules/",

    # Тесты
    "*.test.ts",
    "*.spec.ts",
    "vitest.config.*",
    "test/**",
    "__tests__/**",

    # Переменные окружения / секреты
    ".env",
    ".env.*",

    # Результат сборки
    "dist/",

    # Lock-файлы
    "*.lock",
    "package-lock.json",
    "bun.lock",

    # VCS и OS
    ".git/",
    ".DS_Store",

    # Локальная конфигурация (поставляется через config.example.json)
    "config.json",
]
```

### Когда отклоняться

| Ситуация | Изменение |
|----------|-----------|
| Расширение поставляет `.env.example` как шаблон для пользователя | Заменить `".env.*"` на явные `".env", ".env.local", ".env.development"` |
| У расширения нет конфигурационного файла | Убрать `"config.json"` из exclude |
| Расширение включает тестовые фикстуры в архив | Убрать `"test/**"` |
| Бандл с вложенными пакетами | Добавить префикс `**/` ко всем паттернам (например, `"**/node_modules/**"`) |

## Правила preserve

Массив `preserve` перечисляет файлы в **директории установленного пакета**, которые не должны быть перезаписаны при `store update`.

### Когда использовать

Используйте `preserve`, когда ваше расширение создаёт или ожидает изменённые пользователем файлы в рантайме:

| Файл | Зачем сохранять | Примеры пакетов |
|------|-----------------|-----------------|
| `config.json` | Пользователь настраивает параметры расширения | `fan-orchestrator`, `fan-web-search`, `fan-loop` |
| `.env` | Пользователь хранит API-ключи и секреты | `fan-confluence`, `stack-overflow-agents` |
| `health.json` | Генерируемый в рантайме статус здоровья | `fan-web-search` |

### Когда не использовать

- **Скиллы** — read-only markdown, без изменяемого состояния.
- **Темы** — один JSON-файл, полностью заменяется при обновлении.
- **Расширения без конфигурации** — если все настройки в `package.json` или переменных окружения, сохранять нечего.

### Как это работает

```
Первая установка:
  архив → извлечь → скопировать все файлы в директорию установки
  (preserve не действует — нет существующих файлов)

Обновление:
  архив → извлечь → скопировать файлы, ПРОПУСКАЯ любой путь из preserve
  (пользовательские config.json, .env и т.д. остаются нетронутыми)
```

> **Важно:** пути `preserve` относительны к директории установки пакета, это не glob-паттерны. Они совпадают с точными путями файлов.

## Реальные примеры

### Расширение: `fan-orchestrator`

Дистрибуция скомпилированного JavaScript с промптами агентов и конфигурацией.

```toml
# DEPLOY.toml — FAN Package Deployment Manifest
# Schema version: 1

[package]
name = "fan-orchestrator"
type = "extension"

include = [
    "*.js",
    "*.d.ts",
    "agents/*.js",
    "agents/*.d.ts",
    "agents/*.md",
    "prompts/*.md",
    "package.json",
    "README.md",
    "config.example.json",
]

exclude = [
    "node_modules/",
    "*.test.ts",
    "*.spec.ts",
    "vitest.config.*",
    ".env",
    ".env.*",
    "dist/",
    "*.lock",
    "package-lock.json",
    "bun.lock",
    ".git/",
    ".DS_Store",
    "test/**",
    "config.json",
]

preserve = [
    "config.json",
]
```

### Расширение: `fan-confluence`

Дистрибуция исходников TypeScript с `.env.example` и явными исключениями env.

```toml
# DEPLOY.toml — FAN Package Deployment Manifest
# Schema version: 1

[package]
name = "fan-confluence"
type = "extension"

include = [
    "index.ts",
    "client.ts",
    "config.ts",
    "converters/*.ts",
    "tools/*.ts",
    "package.json",
    "README.md",
    ".env.example",
]

exclude = [
    "node_modules/",
    "*.test.ts",
    "*.spec.ts",
    "vitest.config.*",
    ".env",
    ".env.local",
    ".env.development",
    "dist/",
    "*.lock",
    "package-lock.json",
    "bun.lock",
    ".git/",
    ".DS_Store",
    "tests/**",
]

preserve = [
    ".env",
]
```

> Обратите внимание: `.env.example` в `include`, а `.env`, `.env.local`, `.env.development` перечислены поимённо в `exclude` — это позволяет избежать ловушки `.env.*`, которая также исключила бы файл-пример.

### Скилл: `fan-forge`

Markdown-скилл со справочными документами, скриптами и шаблонами.

```toml
# DEPLOY.toml — FAN Package Deployment Manifest
# Schema version: 1

[package]
name = "fan-forge"
type = "skill"

include = [
    "SKILL.md",
    "package.json",
    "README.md",
    "references/**/*.md",
    "scripts/**/*.sh",
    "templates/**/*",
]

# В скиллах нет генерируемых файлов
exclude = []

# Скиллы — read-only markdown, без клиентского состояния
preserve = []
```

### Бандл: `fan-lavish`

Вложенный бандл, содержащий расширения и скиллы.

```toml
# DEPLOY.toml — FAN Package Deployment Manifest
# Schema version: 1

[package]
name = "fan-lavish"
type = "bundle"

include = [
    "package.json",
    "README.md",
    "extensions/**/*.ts",
    "extensions/**/package.json",
    "extensions/**/*.md",
    "extensions/**/config.example.json",
    "skills/**/SKILL.md",
    "skills/**/package.json",
]

exclude = [
    "**/node_modules/**",
    "**/.env*",
    "**/*.test.*",
    "**/*.spec.*",
    "**/dist/**",
    "**/__tests__/**",
]
```

## Типичные ошибки

### 1. Паттерны директорий без `/**`

```toml
# ❌ Совпадает только с записью директории, не с её содержимым
exclude = ["dist"]

# ✅ Совпадает со всем содержимым dist/
exclude = ["dist/**"]
```

### 2. `.env.*` поглощает `.env.example`

```toml
# ❌ .env.example совпадает с .env.* и исключается
include = [".env.example"]
exclude = [".env.*"]

# ✅ Перечисляем конкретные env-файлы
include = [".env.example"]
exclude = [".env", ".env.local", ".env.development"]
```

### 3. Забытый `package.json`

```toml
# ❌ В архиве нет манифеста — клиент не может определить версию или тип
include = ["index.ts", "README.md"]

# ✅ Всегда включайте package.json
include = ["index.ts", "package.json", "README.md"]
```

### 4. Нерекурсивный `*.ts` для вложенных исходников

```toml
# ❌ Совпадает только с .ts-файлами в корневой директории
include = ["*.ts"]

# ✅ Совпадает с .ts-файлами во всех поддиректориях
include = ["src/**/*.ts"]
```

### 5. Отсутствующие пустые массивы

```toml
# ❌ Отсутствующие ключи вызывают ошибки парсинга
[package]
name = "my-skill"
type = "skill"
include = ["SKILL.md"]

# ✅ Все три массива должны присутствовать
[package]
name = "my-skill"
type = "skill"
include = ["SKILL.md"]
exclude = []
preserve = []
```

### 6. Паттерны бандлов без префикса `**/`

```toml
# ❌ Совпадает только с extensions/ в корне бандла
include = ["extensions/*.ts"]

# ✅ Совпадает на любой глубине вложенности
include = ["extensions/**/*.ts"]
```

### 7. Сохранение файлов, которых нет в архиве

```toml
# ❌ health.json не упакован — preserve не действует
include = ["index.ts", "package.json"]
preserve = ["health.json"]

# ✅ Сохраняйте только файлы, которые расширение создаёт в рантайме
include = ["index.ts", "config.example.json", "package.json"]
preserve = ["config.json"]
```

## Сборка архива

Используйте `DEPLOY.toml` как чек-лист при создании архива `.tar.gz`:

```bash
cd extensions/my-extension

# Прочитать include-паттерны из DEPLOY.toml, затем:
tar -czf "/tmp/my-extension-1.0.0.tar.gz" \
  --transform="s,^\./,my-extension/," \
  ./index.ts ./package.json ./README.md

# Проверить содержимое
tar -tzf "/tmp/my-extension-1.0.0.tar.gz"

# Вычислить хеш для репозитория
sha256sum "/tmp/my-extension-1.0.0.tar.gz"
```

Архив должен содержать одну top-level директорию с именем пакета:

```
my-extension/
├── index.ts
├── package.json
└── README.md
```

## Расширяемость (v2)

Схема v2 может ввести дополнительные секции:

| Секция | Назначение | Статус |
|--------|-----------|--------|
| `[build]` | Команды сборки, точки входа, выходная директория | Запланировано |
| `[dependencies]` | Объявления runtime-зависимостей сверх `package.json` | Запланировано |
| `[hooks]` | Хуки жизненного цикла (скрипты pre-install, post-update) | Запланировано |

Эти секции не распознаются парсерами схемы v1. Пакеты, нацеленные на v1, не должны их использовать.

## Расположение файла

`DEPLOY.toml` находится в **корне директории пакета**, рядом с `package.json`:

```
extensions/fan-orchestrator/
├── DEPLOY.toml          ← здесь
├── package.json
├── index.ts
├── src/
└── ...
```

Каждый публикуемый пакет в `extensions/`, `skills/`, `bundles/` и `themes/` должен иметь `DEPLOY.toml`.
