# Руководство по делегированию в research-spec-generator

> Reference-файл скилла feature-roadmap.
> Полный поток делегирования при превышении лимитов.

## Триггеры делегирования

Делегирование срабатывает при **любом** из условий:

1. **Превышение лимита этапов** — `phaseCount > 8` (п. 3.4 SKILL.md).
2. **Превышение лимита функций** — после Фазы 2 обнаружено `functionCount > 15`.
3. **Множество «too_large_candidate»** — более 30% функций помечены как
   требующие разбиения (см. п. 2.2.1 SKILL.md).
4. **Смешение слоёв в спецификации** — спека описывает одновременно
   > 2 слабо связанных областей (например, «система уведомлений + админка
   + аналитика» в одной спеке).
5. **Явный запрос пользователя** — «разбей на части», «слишком много» и т.п.

---

## Формат передачи данных

Делегирование выполняется **через инструкцию пользователю** (скиллы в FAN
не вызывают друг друга напрямую):

```
🚨 Рекомендация: делегировать в /skill:research-spec-generator

Текущая спецификация: {source_spec_path или описание}
Обнаружено: {N} функций, {M} этапов (лимит: 15 функций / 8 этапов)

Кандидаты на выделение в дочерние спецификации:
1. «Подсистема X» — {N1} функций: {список через запятую}
2. «Подсистема Y» — {N2} функций: {список через запятую}
3. «Подсистема Z» — {N3} функций: {список через запятую}

Предлагаю запустить:
/skill:research-spec-generator {source_spec_path} — выделить в дочернюю спеку: «Подсистема X» (функции: F-1.1, F-1.2, F-2.3)
/skill:research-spec-generator {source_spec_path} — выделить в дочернюю спеку: «Подсистема Y» (функции: F-2.1, F-2.2)
/skill:research-spec-generator {source_spec_path} — выделить в дочернюю спеку: «Подсистема Z» (функции: F-3.1, F-3.2, F-3.3)

После создания дочерних спек запустите /skill:feature-roadmap для каждой:
/skill:feature-roadmap docs/specs/spec_x_2026-06-02.md
/skill:feature-roadmap docs/specs/spec_y_2026-06-02.md
/skill:feature-roadmap docs/specs/spec_z_2026-06-02.md

Если хотите делегировать автоматически (в одном интерактивном сеансе) — 
подтвердите, и я вызову research-spec-generator последовательно для каждой подсистемы.
```

**Структура аргумента** для `research-spec-generator`:
- Запрос = `<source_spec_path или краткое описание>` + ` — выделить в дочернюю спеку: "<имя_подсистемы>" (функции: <список ID>)`
- Тип запроса: «Новая фича» (уже категоризирован)
- Полнота: ~0.6 (агент знает, что выделять, но требует подтверждения)

## Сценарии обработки результата

### Сценарий A: одна новая спецификация → один новый roadmap

- spec-generator создаёт `docs/specs/spec_<subsystem>_<date>.md`
- Запускается `/skill:feature-roadmap <новый_путь>` (в том же сеансе или по запросу)
- Создаётся `docs/features/<subsystem>/roadmap.md`

### Сценарий B: несколько новых спецификаций → несколько roadmap-ов

- spec-generator создаёт N файлов в `docs/specs/`
- Агент предлагает пользователю запустить `/skill:feature-roadmap` для каждого
- ИЛИ, при подтверждении, запускает цикл `for spec in spec_*.md: roadmap(spec)`

### Сценарий C: spec-generator не установлен

- Агент сообщает: «Скилл /skill:research-spec-generator не обнаружен. Установите его через FAN Store (`fan store install research-spec-generator`) или вручную. Пока продолжим с предупреждением.»
- Спрашивает: «Продолжить генерацию roadmap с превышением лимита (Y/n)?»
- Если «да» — продолжает Фазу 4, ставит в шапке roadmap предупреждение
- Если «нет» — прерывает процесс, рекомендует установить скилл

---

## Связь с обособленностью фич

Делегирование **не подменяет** разбиение крупных фич на слои (п. 2.2.1).
Это разные механизмы:

| Механизм | Где работает | Когда |
|----------|-------------|-------|
| **Разбиение фич** | Внутри одного roadmap | Для ясности реализации (слои в одной карточке) |
| **Делегирование в spec-generator** | Между roadmap-ами | Когда весь объём фичи превышает границы (15+ функций, 9+ этапов) |
