# research-spec-generator 📋

**Skill для исследования тем и создания спецификаций.**

Исследует тему из множества источников, проводит итеративное интервьюирование для устранения неопределённостей и создаёт файл спецификации в `docs/specs/`.

---

## Что это

research-spec-generator — это skill, который превращает запрос на естественном языке в полноценный документ исследования или техническое задание.

```
Запрос → Категоризация → Исследование → Уточняющие вопросы → Спецификация
```

### Поддерживаемые типы запросов

| Тип | Описание | Шаблон выхода |
|------|----------|---------------|
| **Исследование** | Изучение технологии, подхода, предметной области | Отчёт с анализом, сравнениями, рекомендациями |
| **Новая фича** | Функционал для существующей системы | Спецификация с требованиями и сценариями |
| **Новый проект** | Создание с нуля | Полное ТЗ с архитектурой и приоритетами |
| **Модификация** | Изменение существующего поведения | Спецификация изменений |
| **Интеграция** | Соединение систем | Спецификация интеграции |
| **Оптимизация** | Улучшение характеристик | Спецификация с метриками и целями |

## Процесс

1. **Инициализация** — категоризация запроса, оценка полноты (0–1)
2. **Исследование** — циклический сбор из всех источников:
   - Память проекта (`memory_search`)
   - Исходный код проекта (`read`, `bash`)
   - Веб (`web_search` → `web_reader`)
3. **Анализ и уточнения** — структурирование + `questionnaire` с блокирующими/важными/рекомендательными вопросами
4. **Обработка ответов** — интеграция ответов, дополнительные исследования при необходимости
5. **Создание спецификации** — выбор шаблона по типу запроса, заполнение, сохранение

---

## Источники исследования

| Приоритет | Инструмент | Что даёт |
|-----------|-----------|----------|
| 1 | `memory_search` | Контекст из прошлых сессий |
| 2 | `read` + `bash` | Текущая архитектура и код проекта |
| 3 | `web_search` | Документация, статьи, best practices |
| 4 | `web_reader` | Глубокое чтение конкретных страниц |

---

## Шаблоны спецификаций

**Для исследований:** Обзор → Детальный анализ → Сравнительный анализ → Выводы → Риски → Источники

**Для спецификаций:** Обзор → Функциональные требования → UI/UX → Нефункциональные требования → Технические требования → Данные → Риски → Tradeoffs → Приоритеты (MoSCoW)

---

## Принципы

- **Цикличность.** Исследование → вопросы → исследование → ... пока есть пробелы
- **Не более 5–7 вопросов** за раунд интервьюирования
- **Блокирующие вопросы — без опции «Пропустить».** Важные — с опцией
- **Не создавай документ** пока интервью не завершено
- **Адаптируй шаблон** — не все разделы нужны для каждого запроса
- **Фиксируй источники** — URL, пути, конкретные данные
