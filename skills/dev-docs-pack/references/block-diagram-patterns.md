# Block Diagram Patterns — Конвенции ASCII-диаграмм

## Общие правила

1. Использовать box-drawing characters: `┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼ │ ─`
2. Стрелки: `→ ← ↑ ↓ ↔`
3. Максимум 80 символов шириной (терминал-френдли)
4. Подписывать соединения
5. Использовать emoji для акцентов (опционально): 🔴 🟢 ⚡ 📦 ✅

---

## Паттерн 1: Системная архитектура (high-level)

Используется в roadmap-main.md для обзора всей фичи.

```
┌──────────────────────────────────────────────────┐
│                Feature Name                      │
├──────────────────────────────────────────────────┤
│                                                  │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐   │
│  │ Module A │───→│ Module B │───→│ Module C │   │
│  └──────────┘    └──────────┘    └──────────┘   │
│       │                │               │        │
│       ▼                ▼               ▼        │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐   │
│  │ Store 1  │    │ Store 2  │    │ Store 3  │   │
│  └──────────┘    └──────────┘    └──────────┘   │
│                                                  │
└──────────────────────────────────────────────────┘
```

**Правила:**
- Внешняя рамка — границы фичи
- Внутренние блоки — модули/компоненты
- Стрелки — direction of data flow
- Нижний ряд — хранилища/сервисы

## Паттерн 2: Компоненты этапа (stage diagram)

Используется в roadmap-stage-N-*.md для конкретного этапа.

```
┌─ Stage N: Stage Name ──────────────────────────┐
│                                                │
│  INPUT: <what enters this stage>               │
│                                                │
│  ┌─────────┐     ┌───────────────┐            │
│  │Component│────→│  Component    │            │
│  │    A    │     │      B        │            │
│  └─────────┘     └───────┬───────┘            │
│                          │                    │
│                   ┌──────▼───────┐            │
│                   │  Component   │            │
│                   │      C       │            │
│                   └──────────────┘            │
│                                                │
│  OUTPUT: <what this stage produces>            │
│  SMOKE: <how to verify>                        │
└────────────────────────────────────────────────┘
```

**Правила:**
- INPUT — от предыдущего этапа
- OUTPUT — для следующего этапа
- SMOKE — краткая инструкция проверки
- Компоненты — конкретные файлы/модули

## Паттерн 3: Data flow

Используется для описания потока данных.

```
User ──→ [API Layer] ──→ [Service] ──→ [Repository] ──→ [DB]
              │                │
              │                └──→ [Event Bus] ──→ [Notifier]
              │
              └──→ [Validator] ──→ [Error Handler]
```

**Правила:**
- Квадратные скобки для обработчиков/слоёв
- Стрелки показывают направление потока
- Ветвления — для альтернативных путей (ошибки, события)

## Паттерн 4: Карта зависимостей этапов

Используется в roadmap-main.md для overview.

```
Stage 1 ──→ Stage 2 ──→ Stage 3 ──→ Stage 4
  (Data)      (Logic)     (API)      (UI)
                  │            │
                  └── Stage ────┘
                      2.5
                    (Auth)
```

**Правила:**
- Горизонтальные стрелки — последовательная зависимость
- Диагональные — cross-stage зависимости
- Подписи в скобках — краткое название

## Паттерн 5: TDD-цикл

Используется в roadmap-stage-N-*.md для описания подхода.

```
┌─── Red ──────────────────────────────────────┐
│  Write failing tests                         │
│  → unit tests for new components             │
│  → integration tests for interfaces          │
│  → smoke test for stage outcome              │
└──────────────┬──────────────────────────────┘
               ▼
┌─── Green ────────────────────────────────────┐
│  Implement minimum code to pass tests        │
│  → new files / components                    │
│  → wire up dependencies                      │
└──────────────┬──────────────────────────────┘
               ▼
┌─── Refactor ─────────────────────────────────┐
│  Improve code quality                        │
│  → extract shared utilities                  │
│  → improve naming                            │
│  → ensure previous stages' tests still pass  │
└──────────────────────────────────────────────┘
```

## Паттерн 6: Wireframe (UI mockup)

Используется в ui-ux/wireframes.md.

```
┌─────────────────────────────────────────┐
│  Header: [Title]                   [X]  │
├─────────────────────────────────────────┤
│                                         │
│  ┌─────────────────────────────────┐    │
│  │  Primary Content Area           │    │
│  │                                 │    │
│  │  [Input Field          ]        │    │
│  │                                 │    │
│  │  ┌─────┐ ┌─────┐ ┌─────┐      │    │
│  │  │ Btn │ │ Btn │ │ Btn │      │    │
│  │  └─────┘ └─────┘ └─────┘      │    │
│  │                                 │    │
│  │  ┌─────────────────────────┐   │    │
│  │  │  List / Table            │   │    │
│  │  │  - Item 1                │   │    │
│  │  │  - Item 2                │   │    │
│  │  │  - Item 3                │   │    │
│  │  └─────────────────────────┘   │    │
│  └─────────────────────────────────┘    │
│                                         │
│  [Footer / Status Bar]                   │
└─────────────────────────────────────────┘
```

**Правила:**
- Использовать реальные тексты (не lorem ipsum)
- Указывать типы элементов: [Input Field], [Btn], [List]
- Отмечать интерактивные элементы
- Ширина до 60 символов для содержимого

---

## Правила форматирования

1. **Символы:** Только `─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼ → ← ↑ ↓ ↔`
2. **Ширина:** Максимум 80 символов на строку
3. **Выравнивание:** По центру для заголовков, по левому краю для содержимого
4. **Пустые строки:** Внутри блоков — для отделения секций
5. **Лейблы:** Краткие, по-русски, по-английски для технических терминов
6. **Без цветов:** Только символы, без ANSI-escape кодов
