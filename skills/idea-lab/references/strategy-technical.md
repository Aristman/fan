# Strategy: Technical Ideas

Используется для: фичи, продукты, архитектура, технологии, интеграции, оптимизация.

---

## Ключевые аспекты для исследования

| # | Аспект | Что выясняем | Типичная неопределённость |
|---|--------|-------------|--------------------------|
| 1 | **Проблема** | Какую боль решаем? Для кого? | Высокая — часто размыта |
| 2 | **Контекст проекта** | Стек, архитектура, constraints | Средняя — частично известно из кода |
| 3 | **Техническая реализуемость** | Возможно ли технически? Какие барьеры? | Средняя — требует исследования |
| 4 | **Стек и технологии** | Какие инструменты? Совместимость? | Средняя — могут быть альтернативы |
| 5 | **Архитектурное решение** | Как интегрируется? Паттерны? | Высокая — требует проектирования |
| 6 | **Альтернативы** | Есть готовые решения? Libraries? SaaS? | Средняя — нужен поиск |
| 7 | **Зависимости и риски** | Блокирующие зависимости? Migration? | Средняя — могут быть скрытые |
| 8 | **Оценка трудозатрат** | Размер задачи? MVP? | Высокая — требует оценки |

---

## Специфичные вопросы для интервью

### Блокирующие
- Какую конкретную проблему решает эта фича/идея?
- Есть ли жёсткие constraints (стек, бюджет, сроки)?
- Что произойдёт если НЕ делать? (cost of inaction)

### Важные
- Есть ли предпочтения по стеку/технологиям?
- Нужна ли обратная совместимость?
- Какие метрики успеха?

### Рекомендательные
- Есть ли референсы / примеры / inspiration?
- Предполагается MVP или полная реализация?
- Кто будет поддерживать?

## Специфичная стратегия web_search

### Запросы по приоритетам

```
1. "<технология/инструмент> best practices 2025-2026"          — общие практики
2. "<конкретная задача> implementation guide"                    — как реализовать
3. "<конкретная задача> alternatives comparison"                 — альтернативы
4. "<инструмент> limitations gotchas"                           — подводные камни
5. "<задача> performance benchmark"                             — если важна производительность
6. site:github.com "<задача>"                                   — реальные реализации
```

### Типичные домены для поиска

| Тип информации | Домены |
|---------------|--------|
| Официальная документация | Официальные сайты технологий |
| Обсуждения | Stack Overflow, Reddit |
| Реализации | GitHub, GitLab |
| Сравнения | stateof.dev, thoughtworks.com/radar |

## Специфичные критерии брейншторма

Для технических альтернатив оценивай по:

| Критерий | Описание |
|----------|----------|
| Реализуемость | Насколько сложно технически реализовать |
| Совместимость | Как встраивается в текущий стек |
| Поддержка | Сообщество, документация, обновления |
| Производительность | throughput, latency, resource usage |
| Масштабируемость | Что будет при росте нагрузки/команды |
| Стоимость | Лицензии, инфраструктура, обучение |
