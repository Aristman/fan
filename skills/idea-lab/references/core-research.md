# Core Research — Общие инструкции для Idea Lab

Этот файл содержит общие механизмы исследования, используемые всеми стратегиями.

---

## 1. Оценка неопределённости

### Методика

Для каждого ключевого аспекта идеи оценивай уверенность по шкале 0–1:

| Уровень | Значение | Действие |
|---------|----------|----------|
| 0.9–1.0 | Точно знаем | Фиксируем, двигаемся дальше |
| 0.7–0.8 | Pretty sure | Быстрая проверка, 1 уточняющий вопрос |
| 0.4–0.6 | Размыто | Исследование + 2-3 вопроса |
| 0.0–0.3 | Не знаем вообще | Глубокое исследование + interview |

### Общая оценка

```
Общая уверенность = (среднее по блокирующим × 0.5) + (среднее по важным × 0.3) + (среднее по рекомендательным × 0.2)
```

Цель: общая уверенность ≥ 0.9.

## 2. Интервьюирование

### Правила вопросов

1. **Максимум 5 вопросов** за один вызов `questionnaire`
2. **Блокирующие** → без опции "Пропустить"
3. **Важные / Рекомендательные** → с опцией "Пропустить"
4. **Предлагай варианты** — не задавай полностью открытые вопросы через questionnaire
5. **Группируй по темам** — сначала блокирующие, потом важные
6. **Резюмируй** промежуточные выводы после каждого раунда

### Структура вопроса

Для questionnaire:
```
{
  id: "уникальный_id",
  label: "Короткий ярлык для таба",
  prompt: "Полный текст вопроса с контекстом",
  options: [
    { value: "val1", label: "Вариант 1", description: "Описание" },
    { value: "val2", label: "Вариант 2" },
    { value: "skip", label: "Пропустить" }  // только для некритичных
  ],
  allowOther: true  // разрешить свободный ввод
}
```

### Цикл уточнения

```
Задал вопросы → получил ответы → интегрировал → оценил полноту
  ↑                                                              ↓
  └──────────── если < 0.9, новые вопросы ←───────────────────────┘
```

## 3. Веб-исследование

### Порядок источников

```
1. memory_search → проектная память (предыдущие исследования, решения, контекст)
2. read + bash   → локальные файлы, код, документация проекта
3. web_search    → глобальный поиск (документация, статьи, обзоры)
4. web_reader    → глубокое чтение конкретных страниц
```

### Стратегия web_search

- **Начни широко:** 1-2 общих запроса по теме
- **Узнай специфику:** 2-3 узких запроса по конкретным аспектам
- **Проверь альтернативы:** 1-2 запроса по альтернативным подходам

Фильтры:
- `recency_filter: "oneYear"` — для технологий и рынка
- `recency_filter: "noLimit"` — для фундаментальных концепций
- `domain_filter` — для официальной документации

### Фиксация источников

Для каждого результата:
```
- **[Название]** — краткое описание (1 предложение)
  URL: <ссылка>
  Релевантность: Высокая/Средняя/Низкая
  Ключевые выводы: ...
```

## 4. SWOT-анализ

### Формат

```
### Strengths (Сильные стороны) 🔵
Внутренние преимущества идеи.
- [Факт с обоснованием]

### Weaknesses (Слабые стороны) 🟠
Внутренние недостатки и ограничения.
- [Факт с обоснованием]

### Opportunities (Возможности) 🟢
Внешние благоприятные факторы.
- [Факт с обоснованием]

### Threats (Угрозы) 🔴
Внешние неблагоприятные факторы.
- [Факт с обоснованием]
```

### Правила

- Каждая позиция — **конкретный факт**, не абстракция
- Минимум 2 позиции в каждом квадранте
- Указывай **обоснование** (источник данных)
- Учитывай контекст пользователя (его навыки, ресурсы, проект)

## 5. Брейншторм альтернатив

### Методика

1. **Сгенерируй минимум 3 альтернативы** — включая «ничего не делать» как базовый вариант
2. **Для каждой укажи:**
   - Суть (1-2 предложения)
   - Ключевые плюсы (2-3)
   - Ключевые минусы (2-3)
   - Сложность реализации (Низкая/Средняя/Высокая)
   - Ориентировочное время
   - Ключевые риски
3. **Сравнительная матрица** — оцени по 4-6 критериям (⭐1-5)
4. **Рекомендация** — какая альтернатива лучше и почему

### Правила

- Не придумывай альтернативы из воздуха — опирайся на исследование
- «Ничего не делать» — валидная альтернатива, если риски внедрения превышают выгоды
- Учитывай ресурсы пользователя (время, бюджет, навыки)
- Если альтернативы комбинируются — укажи это

## 6. Оценка полноты исследования

### Критерии

| Критерий | Что проверяем | Вес |
|----------|---------------|-----|
| Полнота охвата | Все ключевые аспекты затронуты | 0.3 |
| Актуальность | Источники свежие и релевантные | 0.2 |
| Разнообразие | Учитываются разные перспективы | 0.2 |
| Практичность | Результаты применимы к контексту | 0.3 |

### Пороги по глубине

| Глубина | Порог перехода | Макс. раундов исследования | Макс. раундов вопросов |
|---------|---------------|---------------------------|----------------------|
| Quick scan | 0.7 | 1 | 1 |
| Стандартный | 0.8 | 2 | 3 |
| Глубокий | 0.9 | 4 | 5 |

## 7. Принятие решений

### Формат рекомендации

```
## Рекомендация

### Что делать: <Название подхода>
**Уверенность:** 0.X/1.0

**Обоснование:**
1. <Причина 1 с данными>
2. <Причина 2 с данными>
3. <Причина 3 с данными>

**Компромиссы:**
- Принимаем: <что жертвуем и почему это OK>
- Отклоняем: <что не рассматриваем и почему>

**Предупреждения:**
- ⚠️ <Риск 1 и митигация>
- ⚠️ <Риск 2 и митигация>
```

### Правила

- **Уверенность < 0.7** — не рекомендуй, укажи что данных недостаточно
- **Уверенность 0.7–0.85** — рекомендуй с оговорками
- **Уверенность > 0.85** — рекомендуй уверенно
- Всегда указывай альтернативу на случай ошибки
