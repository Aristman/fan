# Idea Lab — Исследователь и анализатор идей

Skill для глубокого исследования идей: от размытой мысли до структурированного документа с решениями.

## Типы идей

| Тип | Когда использовать | Ключевые аспекты |
|------|-------------------|------------------|
| **technical** | Фичи, продукты, архитектура, технологии | Реализуемость, стек, риски, tradeoffs |
| **business** | Стартапы, рынки, монетизация, стратегии | Рынок, конкуренты, unit economics, MVP |
| **creative** | Контент, дизайн, маркетинг, кампании | Аудитория, формат, каналы, KPI |

## Доступные инструменты

Для интерактивного диалога с пользователем используй tools `question` и `questionnaire` (расширение **fan-ask-answer**):

- **`question`** — один вопрос с вариантами
- **`questionnaire`** — серия вопросов с таб-навигацией

## Процесс

### Фаза 1: Инициализация

**1.1 Зафиксируй исходный запрос**

```
Ядро идеи: <краткое описание>
```

**1.2 Определи тип идеи**

Анализируй описание и определи тип: `technical` / `business` / `creative`.
Используй `question` для подтверждения:

```
question({
  question: "Определяю тип идеи как «<тип>». Верно?",
  options: [
    { label: "Да", value: "yes" },
    { label: "Нет, техническая", value: "technical" },
    { label: "Нет, бизнес", value: "business" },
    { label: "Нет, креативная", value: "creative" }
  ]
})
```

**1.3 Загрузи стратегию**

Прочитай файл стратегии для определённого типа:
- Техническая: [strategy-technical.md](references/strategy-technical.md)
- Бизнес: [strategy-business.md](references/strategy-business.md)
- Креативная: [strategy-creative.md](references/strategy-creative.md)

**1.4 Спроси глубину исследования**

```
question({
  question: "Какая глубина исследования?",
  options: [
    { label: "Quick scan", description: "3-5 минут, быстрый анализ, минимальный опрос", value: "quick" },
    { label: "Стандартный", description: "10-20 минут, основное исследование", value: "standard" },
    { label: "Глубокий", description: "30+ минут, глубокий dive с несколькими циклами", value: "deep" }
  ]
})
```

**1.5 Оцени полноту запроса (0–1)**

| Оценка | Описание |
|--------|----------|
| 0.9–1.0 | Всё ясно, минимум уточнений |
| 0.7–0.8 | Понятно, нужны 1–2 уточнения |
| 0.4–0.6 | Тема ясна, цель размыта |
| 0.0–0.3 | Существенное уточнение |

### Фаза 2: Оценка неопределённости

Прочитай [core-research.md](references/core-research.md) для общих инструкций.

**2.1 Определи области неопределённости**

Для каждого аспекта (из загруженной стратегии) оцени:

| Аспект | Что знаем | Что не знаем | Уровень уверенности (0–1) |
|--------|-----------|---------------|--------------------------|
| ... | ... | ... | ... |

**2.2 Матрица пробелов знаний**

Категоризируй пробелы:
- 🔴 **Блокирующие** — без ответа невозможно принять решение
- 🟡 **Важные** — влияют на качество решения
- 🟢 **Рекомендательные** — улучшат полноту, но не блокируют

**2.3 Матрица рисков**

| Риск | Вероятность | Влияние | Категория |
|------|-------------|---------|-----------|
| ... | Высокая/Средняя/Низкая | Критичное/Среднее/Низкое | Технический/Рыночный/Ресурсный |

**Критерий:** Средний уровень уверенности ≥ 0.9 по всем блокирующим аспектам → переход к Фазе 3.

### Фаза 3: Сбор информации (циклическая)

Повторяй до достижения целевого уровня.

#### 3.1 Опрос пользователя

Сформулируй вопросы на основе пробелов из Фазы 2.
Используй `questionnaire` (не более 5 вопросов за раз):
- 🔴 Блокирующие — без опции "Пропустить"
- 🟡 Важные / 🟢 Рекомендательные — с опцией "Пропустить"

#### 3.2 Веб-исследование

**Приоритет источников:**
1. `memory_search` — проектная память
2. `read` + `bash` — локальные файлы, код
3. `web_search` — веб-поиск
4. `web_reader` — глубокое чтение страниц

**Стратегия поиска по типу идеи:**
- Техническая: документация, GitHub, StackOverflow, benchmark'и
- Бизнес: рыночные отчёты, конкуренты, case studies
- Креативная: тренды, best practices, примеры, аудитория

#### 3.3 Оценка полноты

После каждого раунда оцени:

| Критерий | Оценка (0–1) |
|----------|--------------|
| Полнота охвата темы | |
| Актуальность источников | |
| Разнообразие перспектив | |
| Практическая применимость | |

**Quick scan:** Средний ≥ 0.7 → Фаза 4
**Стандартный:** Средний ≥ 0.8 → Фаза 4
**Глубокий:** Средний ≥ 0.9 → Фаза 4

## Правила языка и стиля документа

**Документ пишется на русском языке.** Полностью. Каждое предложение — грамматически корректная русская фраза.

| Что писать по-русски | Что оставлять по-английски |
|----------------------|--------------------------|
| Все описания, суждения, объяснения | Имена собственные: Claude Code, fan, Anthropic |
| Концепции и идеи (объяснённые, а не названные) | Названия API: `fan.registerTool()`, `fan.on("tool_call")` |
| Причины, обоснования, выводы | Имена файлов и путей: `coordinatorMode.ts` |
| Названия разделов, заголовков таблиц | CLI команды: `fan --mode server`, `git commit` |
| Содержимое ячеек таблиц | Ключевые слова языков программирования |
| Артефактные понятия — переводить: plan mode → режим планирования, worker → воркер, coordinator → координатор, spawn → порождение/запуск | Символы статуса: PASS, FAIL, VERDICT |
| Идиомы и метафоры — переводить: game-changer → прорывное решение, battle-tested → проверенный на практике, workaround → обходной путь, workaround (нет прямого аналога — лучше «обходной приём») | |

**Запрещено:**
- ❌ «Pi extension system — ready-made foundation» (английская фраза вместо русского описания)
- ❌ «Claude Code locked на Anthropic» (костыльная вставка английского слова)
- ❌ «model routing — unique advantage» (английская формулировка вместо объяснения)
- ❌ «overhead > benefit» (математическое выражение в тексте вместо слов)
- ❌ «deep dive'ы» (псевдорусское слово от английского)

**Разрешено:**
- ✅ «Система расширений fan — готовая основа для построения оркестратора»
- ✅ «Claude Code привязан к моделям Anthropic»
- ✅ «Маршрутизация моделей — главное преимущество перед Claude Code»
- ✅ «Накладные расходы превышают выгоду при простых задачах»
- ✅ «Подробное изучение исходного кода fan»

## Правила

1. **Оценивай полноту** — если ≤ 0.9, спрашивай. Не додумывай.
2. **Цикличность** — исследование → вопросы → исследование → ... до полноты
3. **Брейншторм всегда** — минимум 3 альтернативы, даже если ответ очевиден
4. **SWOT обязателен** — для любого типа идеи
5. **Конкретика** — не "возможно стоит рассмотреть", а "рекомендую X потому что Y"
6. **Риски честно** — если идея херня — скажи. С аргументами.
7. **Финальный документ** — полный, самодостаточный, без "TODO: уточнить"
8. **Не повторяй** уже проведённое исследование без причины
9. **Фиксируй источники** — URL, пути, конкретные данные
10. **Адаптируйся** — для quick scan меньше вопросов, для deep — больше циклов
