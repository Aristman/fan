# Шаблон спецификации (feature-factory)

> Reference-файл скилла feature-factory.
> Адаптация шаблона скилла research-spec-generator (`references/spec-template.md`)
> под последующую автоматическую генерацию роадмапы: секция **«Функции»** структурирована
> машинно-читаемыми полями, чтобы фаза роадмапы (`references/roadmap-phase.md`) брала
> функции по полям, а не эвристиками по заголовкам.

## Правила заполнения секции «Функции»

1. **Одна запись = одна функция.** ID присваивается при генерации: `F-<порядковый номер>` (F-1, F-2, ...). Фаза роадмапы переприсвоит ID в формат `F-X.Y` (этап.номер).
2. **Приоритет** — либо напрямую `P0|P1|P2|P3`, либо MoSCoW: `Must Have | Should Have | Could Have | Won't Have`. MoSCoW переводится автоматически по `config.roadmap.priorityMapping` из активного конфига (дефолт: Must Have → P0, Should Have → P1, Could Have → P2, Won't Have → исключить из roadmap).
3. **Слой** — ровно одно значение: `API | UI | storage | model | integration | business | cli`.
   Маппинг в слои роадмапы (обособленность фич):

   | Слой в спеке | Слой в roadmap |
   |--------------|----------------|
   | `API` | `[API]` |
   | `UI` | `[UI]` |
   | `storage` | `[DATA]` |
   | `model` | `[DATA]` |
   | `integration` | `[INTEG]` |
   | `business` | `[BIZ]` |
   | `cli` | `[CLI]` |

4. **Одна функция не должна смешивать слои.** Если функция требует и API, и UI — раздели её на две записи.
5. Функции с приоритетом `Won't Have` (→ `exclude`) **не попадают в roadmap**, но остаются в спеке с обоснованием.

- **Тип**: [Новая фича / Новый проект / Модификация / Интеграция / Оптимизация / Исследование]

## Опциональная секция «Источники исследования»

Если исследование (`config.spec.research`) выполнялось — добавь в конец файла:

```markdown
## Приложение: Источники исследования

| Источник | Тип | Что найдено |
|----------|-----|-------------|
| memory_search("...") | память | [кратко] |
| src/... | файл проекта | [кратко] |
| https://... | web | [кратко] |
```
