# bug-fix

## Описание

Стадийный конвейер исправления багов (v2 — координаторский скилл-оркестратор).
Получает описание бага в любом виде → находит корневую причину (RCA-воркер) → оформляет
документ решения → получает **обязательный аппрув оператора** (Lavish, фолбэк `question`) →
пишет красные тесты на все кейсы бага → чинит код минимальным диффом → верифицирует
независимым verify-воркером. Resumable по `state.json`.

**Главное отличие от v1:** фикс без утверждённого документа не выполняется. Сначала причина
и план, потом тесты, потом код.

## Установка

```bash
fan store install bug-fix
```

Или вручную:
```bash
cp -r skills/bug-fix/ ~/.fan/agent/skills/bug-fix/
```

После установки — `/reload`.

## Использование

```bash
/skill:bug-fix Падает тест session при switchSession                       # свободный текст
/skill:bug-fix docs/tickets/TICKET-42.md                                   # тикет/дока/спека
/skill:bug-fix "TypeError: cannot read properties of undefined at session-switch.ts:87"  # stack trace
/skill:bug-fix bug-session-switch-crash                                    # resume по slug
/skill:bug-fix docs/bugs/bug-session-switch-crash/bug.md                   # resume по документу
/skill:bug-fix --hotfix Критичный прод-инцидент, чинить немедленно         # hotfix (аппрув post-hoc)
/skill:bug-fix                                                             # найти свежий прогон и resume
```

Флаг `--hotfix` — только по явному решению оператора: документ пишется с пометкой
`HOTFIX — аппрув post-hoc`, в финале запрашивается ретроспективное ревью. Дефолтом не является.

## Схема стадий

```
Стадия 0: Intake (координатор)
  └── Нормализация входа → .fan/bug-fix/<slug>/intake.md + state.json

Стадия 1: RCA (воркер code-research, read-only)
  ├── Воспроизведение — best effort на текущем окружении → baseline; трассировка причины;
  │   гипотезы (локальный repro не обязателен: баг может жить только на ином окружении)
  ├── Fast-path: claimedRootCause задан → только подтвердить/опровергнуть
  └── confirmed / refuted / not_reproducible (не стоп: шаги repro + окружение → bug.md)

Стадия 2: Документ решения + аппрув (координатор)
  ├── docs/bugs/<slug>/bug.md: Проблема, RCA, Решение, Тест-план TC-BUG-<slug>-N, Риски
  ├── Lavish: playbook("plan") → HTML-превью → open → poll → правки в markdown → approve
  │   (лимит 5 итераций; детально — references/lavish-approval.md)
  ├── Фолбэк: question (approve / правки текстом / abort) — те же 5 итераций
  └── Без аппрува — продолжение запрещено (искл. hotfix)

Стадия 3: Red (воркер tests-impl)
  ├── Каждый TC тест-плана покрыт тестом (существующие — переиспользовать)
  └── Обязательный FAIL на текущем коде, падение по правильной причине

Стадия 4: Green (воркер bug-fix)
  └── Минимальный дифф до зелёных red-тестов; diff-summary

Стадия 5: Verify (воркер verify, независимый)
  ├── Build + полный suite + red-тесты зелёные + фикс чинит причину
  └── FAIL → возврат на Green; максимум 3 цикла Green↔Verify

Стадия 6: Финал (координатор)
  └── bug.md → Fixed + «Результат»; коммит fix(<scope>): ...; отчёт; state → done
```

Координатор код не пишет: 1 стадия = 1 воркер = 1 задача (`delegate_task`). После intake —
ноль вопросов: все развилки решаются документом и его аппрувом (исключения: отсутствие
шагов repro, неоднозначный Red). Шагов repro нет во входе → координатор запрашивает их у
оператора на Intake — законный вопрос вне аппрува.

## Артефакты

| Артефакт | Путь | Коммитится |
|---|---|---|
| Документ решения | `docs/bugs/<slug>/bug.md` | да (вместе с фиксом) |
| Intake-карточка | `.fan/bug-fix/<slug>/intake.md` | нет |
| State/resume | `.fan/bug-fix/<slug>/state.json` | нет |
| HTML-превью | `.fan/bug-fix/<slug>/bug-preview.html` | нет |

## Зависимости

- **orchestrator extension** — `delegate_task`, `TaskCreate`/`TaskUpdate`/`TaskClear`; типы
  воркеров: `code-research`, `tests-impl`, `bug-fix`, `verify`
- **lavish extension** — аппрув документа решения (основной путь)
- **question** (fan-ask-answer) — фолбэк аппрува, когда lavish недоступен

## Changelog

### 2.1.0
Новая семантика воспроизведения: локальный repro — best effort, документирование шагов —
обязательно.

- **Стадия 1:** «Воспроизвести» → «Воспроизвести — best effort на текущем окружении». Баг
  может воспроизводиться только на ином окружении (OS, устройство, данные, конфиг) —
  неудача локального repro НЕ блокирует пайплайн.
- **Критерий выхода RCA:** задокументированные шаги воспроизведения (команда или
  manual-сценарий на указанном окружении) вместо команды воспроизведения; само
  воспроизведение не обязательно.
- **`not_reproducible` — не стоп:** шаги repro и целевое окружение фиксируются в bug.md с
  пометкой «воспроизведение — на окружении X по шагам 1–N», Red — manual-сценарий,
  Verify — build + manual-сценарий. Вопрос «контекст / best-effort / abort» убран.
- **Intake:** шагов repro нет во входе → координатор запрашивает их у оператора (законный
  вопрос вне аппрува).
- **Шаблон bug.md:** шаги repro + целевое окружение обязательны даже без локального
  воспроизведения.

### 2.0.0
Полный редизайн: автономный воркер-фиксер → координаторский скилл-оркестратор.

- **Новый процесс:** intake → RCA воркером → документ решения с обязательным аппрувом
  оператора (Lavish, фолбэк question) → Red-тесты на все кейсы → Green минимальный фикс →
  независимая верификация. В v1 фикс выполнялся одним автономным агентом без аппрува.
- **Аппрув документа обязателен** (`Нет аппрува — нет фикса`), исключение — явный `--hotfix`
  (аппрув post-hoc). В v1 интерактива не было вовсе.
- **Resumable:** состояние в `.fan/bug-fix/<slug>/state.json`; resume по slug, пути к
  `bug.md` или без аргумента (свежий прогон).
- **RCA отдельной стадией** воркером `code-research` с fast-path по заявленной причине;
  документ подсвечивает «Заявленная причина vs найденная».
- **Red-Green:** тесты на все кейсы тест-плана пишутся до фикса и обязаны падать по
  правильной причине; `skip`/заглушки/ослабленные ассерты запрещены.
- **Лимиты:** 5 итераций аппрува, 3 цикла Green↔Verify — исчерпание → честный стоп с отчётом.
- **Worker-инструкция Green** встроена в SKILL.md (вне `worker:exclude`-маркеров) —
  координатор вкладывает её в контекст bug-fix-воркера.
- **Рефакторинг-стадии нет сознательно** — рефакторинг ≠ фикс.

### 1.0.0
Initial release — автономный агент: описание бага → воспроизведение → корневая причина →
минимальный фикс → верификация (build + tests). Формат Bug Fix Report.
