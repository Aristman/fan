# deep-dive 🔬

**Skill для углублённого анализа репозитория по пунктам из отчёта repo-explorer.**

Берёт отчёт `repo-explorer`, извлекает секцию «Следующие шаги» и для каждого выбранного пункта проводит глубокое исследование исходного кода — читает файлы, трассирует зависимости, синтезирует выводы. Каждый пункт → отдельный отчёт.

---

## Что это

deep-dive — это skill, который превращает поверхностный обзор репозитория в глубокое понимание конкретных модулей и подсистем.

| Вход | Выход |
|------|-------|
| Отчёт `repo-explorer` с секцией «Следующие шаги» | Детальные отчёты по каждому выбранному пункту |

**Четыре фазы для каждого пункта:**
1. **Скоупинг** — маппинг пункта на конкретные файлы и модули
2. **Чтение и анализ** — циклическое чтение исходников с оценкой качества (порог ≥ 0.8)
3. **Синтез** — структурирование находок: архитектура, паттерны, tradeoffs
4. **Генерация отчёта** — сохранение markdown-документа с ссылками на конкретные строки кода

## Как использовать

### Запуск

```
/deep-dive <путь-к-отчёту> [номера-через-пробел]
```

**Примеры:**
```
/deep-dive docs/repo-research/NousResearch-hermes-agent/Hermes Agent исследование.md
/deep-dive docs/repo-research/NousResearch-hermes-agent/Hermes Agent исследование.md 1 3 5
```

Если путь или номера не указаны — skill предложит выбор через интерактивный UI.

### После выполнения

- Родительский отчёт обновляется: `- [ ]` → `- [x]` со ссылкой на deep dive
- Все отчёты сохраняются в ту же директорию, что и родительский

## Файловая структура

```
deep-dive/
└── SKILL.md          # Инструкции для LLM
```

**Выходные файлы** (в директории родительского отчёта):
```
docs/repo-research/<repo-name>/
├── <Родительский отчёт>.md
├── Deep Dive — Agent loop run_agent.py.md
├── Deep Dive — Tool lifecycle и orchestration.md
└── Deep Dive — Terminal backend abstraction.md
```

## Источники кода

deep-dive ищет исходники в порядке приоритета:
1. **Локальный клон** — поддиректория в `cwd` с именем репозитория
2. **GitHub raw** — `https://raw.githubusercontent.com/...` (если платформа — GitHub)
3. **У пользователя** — спрашивает путь через `question`, если первые два не сработали

---

## Принципы

- **Код — primary source.** Веб-поиск — только для дополнения, не замена
- **Конкретность.** Каждый вывод со ссылками на файлы, функции, строки
- **Один отчёт — один пункт.** Не смешивай разные пункты
- **Не повторяй.** Deep dive — углубление, не пересказ родительского отчёта
- **Лимиты:** макс. 30 файлов, глубина трассировки — 2 уровня
